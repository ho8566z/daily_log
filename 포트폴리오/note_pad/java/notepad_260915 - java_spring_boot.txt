#### Log4j2 설정과 사용(Log4j2.xml)

```xml
<?xml version="1.0" encoding="UTF-8" ?>
<configuration status="WARN">

<!-- 로그 설정에 사용할 변수를 설정 -->
<Properties>
    <Property name="LOG_PATTERN">%d{yyyy-MM-dd HH:mm:ss} %-5p [%c{3}] - %m%n</Property>
                        <!-- {로그 출력할 때,원하는 형식} / $-5p :로그 레벨 /
                        패키지 단계를 {n}글자만큼 보겠다는 의미 /
                        $m$n : m은 로그 메세지, n은 개행하라는 의미-->
    <Property name="LOG_PATH">logs</Property>
</Properties>

<!-- 로그를 출력할 대상 설정 -->
<Appenders>
    <!-- 콘솔 출력 -->
    <Console name="Console" target="SYSTEM_OUT">
        <PatternLayout pattern="${LOG_PATTERN}" />
    </Console>

    <!-- 파일 기록 : ROOT -->
    <File name="FileForRootByInfo" fileName="${LOG_PATH}/spring-root-info.log">
        <PatternLayout pattern="${LOG_PATTERN}" />
        <Filters>
            <ThresholdFilter level="INFO" onMatch="ACCEPT" onMismatch="DENY" />
        </Filters>
    </File>

    <!-- 파일 기록 : APPLICATION -->
    <!-- INFO 이상 -->
    <!--
    <File name="FileForAppByInfo" fileName="${LOG_PATH}/spring-app-info.log">
        <PatternLayout pattern="${LOG_PATTERN}" />
        <Filters>
            <ThresholdFilter level="INFO" onMatch="ACCEPT" onMismatch="DENY" />
        </Filters>
    </File>
    -->

    <!-- DEBUG 한정 -->
    <File name="FileForAppByDebug" fileName="${LOG_PATH}/spring-app-debug.log">
        <PatternLayout pattern="${LOG_PATTERN}" />
        <Filters>
            <LevelRangeFilter minLevel="DEBUG" maxLevel="DEBUG" onMatch="ACCEPT" onMismatch="DENY" />
        </Filters>
    </File>

    <!-- INFO 한정 -->
    <File name="FileForAppByInfo" fileName="${LOG_PATH}/spring-app-info.log">
        <PatternLayout pattern="${LOG_PATTERN}" />
        <Filters>
            <LevelRangeFilter minLevel="INFO" maxLevel="INFO" onMatch="ACCEPT" onMismatch="DENY" />
        </Filters>
    </File>

    <!-- WARN 한정 -->
    <File name="FileForAppByWarn" fileName="${LOG_PATH}/spring-app-warn.log">
        <PatternLayout pattern="${LOG_PATTERN}" />
        <Filters>
            <LevelRangeFilter minLevel="WARN" maxLevel="WARN" onMatch="ACCEPT" onMismatch="DENY" />
        </Filters>
    </File>

    <!-- ERROR 한정 -->
    <File name="FileForAppByError" fileName="${LOG_PATH}/spring-app-error.log">
        <PatternLayout pattern="${LOG_PATTERN}" />
        <Filters>
            <LevelRangeFilter minLevel="ERROR" maxLevel="ERROR" onMatch="ACCEPT" onMismatch="DENY" />
        </Filters>
    </File>
</Appenders>

<!-- 로그를 남기를 로거(Logger) 설정 -->
<Loggers>
    <!-- 기본 로거 -->
    <Root level="info">
        <AppenderRef ref="Console" />
        <AppenderRef ref="FileForRootByInfo" />
    </Root>

    <!-- Application 로거 -->
    <Logger name="com.office" level="debug" additivity="false">
        <AppenderRef ref="Console" />
        <AppenderRef ref="FileForAppByDebug" />      <!-- Debug 전용 -->
        <AppenderRef ref="FileForAppByInfo" />      <!-- Info 전용 -->
        <AppenderRef ref="FileForAppByWarn" />      <!-- Warn 전용 -->
        <AppenderRef ref="FileForAppByError" />      <!-- Error 전용 -->
    </Logger>
</Loggers>

</configuration>
```

#### Properties

| 이름 | 값 | 의미 |
| --- | --- | --- |
| LOG_PATTERN | %d{yyyy-MM-dd HH:mm:ss} %-5p [%c{3}] - %m%n | 로그 한 줄의 출력 형식 (시간, 레벨, 로거명 3단계, 메시지) |
| LOG_PATH | logs | 로그 파일이 저장될 폴더 경로 |

#### Appenders (출력 대상)

| Appender 이름 | 출력 위치 | 필터 종류 | 통과 조건 | 담기는 로그 |
| --- | --- | --- | --- | --- |
| Console | 화면(콘솔) | 없음 | 전부 통과 | 모든 레벨 |
| FileForRootByInfo | spring-root-info.log | ThresholdFilter | INFO 이상 전부 | INFO, WARN, ERROR, FATAL |
| FileForAppByDebug | spring-app-debug.log | LevelRangeFilter | DEBUG 만 | DEBUG |
| FileForAppByInfo | spring-app-info.log | LevelRangeFilter | INFO 만 | INFO |
| FileForAppByWarn | spring-app-warn.log | LevelRangeFilter | WARN 만 | WARN |
| FileForAppByError | spring-app-error.log | LevelRangeFilter | ERROR 만 | ERROR |

#### Loggers (누구의 로그를 어디로 보낼지)

| 로거 이름 | 대상 패키지 | 자체 레벨 | additivity | 연결된 Appender | 의미 |
| --- | --- | --- | --- | --- | --- |
| Root | 위 Logger에 안 걸리는 모든 것 (예: org.springframework 등) | info | (기본값) | Console, FileForRootByInfo | INFO 이상을 콘솔 + 한 파일에 뭉뚱그려 기록 |
| com.office | com.office로 시작하는 패키지 (애플리케이션 코드) | debug | false | Console, Debug/Info/Warn/Error 파일 4개 | DEBUG부터 전부 받되, 레벨별로 파일을 완전히 분리해서 저장. Root로는 전달 안 함 |

#### 필터 두 종류 비교

| 필터 | 조건 지정 방식 | 동작 | 사용된 곳 |
| --- | --- | --- | --- |
| ThresholdFilter | level="INFO" (기준 하나) | 그 레벨 이상 전부 허용 | FileForRootByInfo |
| LevelRangeFilter | minLevel, maxLevel (범위) | 지정한 범위 안만 허용 (min=max면 그 레벨만) | FileForAppByDebug/Info/Warn/Error |

#### Logger VS. System.out.println()

| 기준 | System.out.println() | Logger |
| --- | --- | --- |
| 켜고 끄기 | 불가능 (코드 삭제만 가능) | 레벨(DEBUG~ERROR)로 제어 |
| 실행 시점 제어 | 항상 실행됨 | 레벨 미달 시 연산 자체를 건너뜀 |
| 출력 위치 | 콘솔 고정 | 콘솔/파일/외부 시스템 등 자유 |
| 메타정보 | 없음 (내가 직접 문자열로 넣어야) | 시간·클래스명·스레드 자동 포함 |
| 성능 | 항상 동기, 즉시 flush | 비동기 지원, 레벨 필터링 |
| 예외 처리 | printStackTrace() 따로 호출 | log.error(msg, e) 한 줄 |
| 운영 환경 재현성 | 재시작하면 로그 증발 | 파일/외부 저장소에 남음 |
| 실무 사용 | ❌ 지양 | ✅ 표준 |

#### 날짜별 + 로그레벨별 파일 생성

- RollingFile + TimeBasedTriggeringPolicy를 사용한다.

```xml
<Appenders>
<!-- DEBUG 전용, 날짜별 롤링 -->
<RollingFile name="FileForAppByDebug"
fileName="{LOG_PATH}/debug/spring-app-debug.log"
                 filePattern="{LOG_PATH}/debug/%d{yyyy-MM-dd}/spring-app-debug-%d{yyyy-MM-dd}-%i.log">
<PatternLayout pattern="${LOG_PATTERN}" />
<Filters>
<LevelRangeFilter minLevel="DEBUG" maxLevel="DEBUG" onMatch="ACCEPT" onMismatch="DENY" />
</Filters>
<Policies>
<TimeBasedTriggeringPolicy interval="1" modulate="true" />
</Policies>
<DefaultRolloverStrategy max="30" /> <!-- 최근 30일치만 보관 -->
</RollingFile>

<!-- INFO 전용, 날짜별 롤링 -->
<RollingFile name="FileForAppByInfo"
             fileName="${LOG_PATH}/info/spring-app-info.log"
             filePattern="${LOG_PATH}/info/%d{yyyy-MM-dd}/spring-app-info-%d{yyyy-MM-dd}-%i.log">
    <PatternLayout pattern="${LOG_PATTERN}" />
    <Filters>
        <LevelRangeFilter minLevel="INFO" maxLevel="INFO" onMatch="ACCEPT" onMismatch="DENY" />
    </Filters>
    <Policies>
        <TimeBasedTriggeringPolicy interval="1" modulate="true" />
    </Policies>
    <DefaultRolloverStrategy max="30" />
</RollingFile>

<!-- WARN, ERROR도 동일 패턴으로 추가 -->
</Appenders>
```

- interval="1" → 1일 단위로 롤링한다.(시간 단위면 filePattern의 패턴을 yyyy-MM-dd-HH로, interval도 조정한다.)
- modulate="true" → 자정 기준으로 정확히 끊어준다.(예: 앱을 오후 3시에 켜도 자정마다 롤링한다.)
- filePattern에 %d{yyyy-MM-dd}가 들어가야 날짜별 파일명이 생성된다.
- DefaultRolloverStrategy max="30" → 오래된 로그 자동 삭제한다.(보관 개수 제한)

#### 용량 기준 + 로그 레벨 별로 파일 생성

- RollingFile + SizeBasedTriggeringPolicy를 사용한다.

```xml
<Appenders>
<!-- DEBUG 전용, 용량 기준 롤링 -->
<RollingFile name="FileForAppByDebug"
fileName="{LOG_PATH}/debug/spring-app-debug.log"
                 filePattern="{LOG_PATH}/debug/spring-app-debug-%i.log.gz">
<PatternLayout pattern="${LOG_PATTERN}" />
<Filters>
<LevelRangeFilter minLevel="DEBUG" maxLevel="DEBUG" onMatch="ACCEPT" onMismatch="DENY" />
</Filters>
<Policies>
<SizeBasedTriggeringPolicy size="10MB" />
</Policies>
<DefaultRolloverStrategy max="10" /> <!-- 최근 10개 파일만 보관 -->
</RollingFile>

<!-- INFO, WARN, ERROR도 동일 패턴으로 추가 -->

</Appenders>
```

**핵심 포인트**

- size="10MB" → 파일이 10MB 넘으면 새 파일로 교체한다.
- filePattern에 %i(인덱스 번호) 필요하면, — spring-app-debug-1.log.gz, spring-app-debug-2.log.gz... 순서로 생성한다.
- .gz 확장자를 붙이면 롤링될 때 자동 압축된다.(안 붙이면 압축 안 한다.)
- DefaultRolloverStrategy max="10" → 오래된 파일부터 자동 삭제한다.

## MyBatis 란?

- SQL을 직접 작성하는 SQL 매퍼(Mapper) 프레임워크이다.
- 순수 JDBC에서 반복적으로 작성하는 Connection 생성·관리, PreparedStatement 파라미터 설정, ResultSet 처리, 자원 반납 등의 작업을 줄여준다.
- 개발자는 주로 SQL과 SQL 결과를 자바 객체에 어떻게 매핑할지에 집중할 수 있다.

#### 매퍼 란?

- 자바 메서드 호출을 SQL 실행으로 연결해주는 중간 다리이다.
- 예를 들어 memberMapper.findById(1L)을 호출하면 → 연결된 SQL이 실행되고 → 조회 결과가 Member 객체로 매핑되어 반환된다.
- 즉, 자바에서 SQL을 호출하고 그 결과를 객체로 받기 위한 연결 역할을 한다.

#### 매퍼 인터페이스 VS. XML 매퍼

| 매퍼 인터페이스 | SQL을 호출하기 위한 자바 쪽 규격(입구) |
| --- | --- |
| XML 매퍼 | 실제로 실행할 SQL과 매핑 정보를 작성하는 곳 |

```smalltalk
JBDC → JBDCTemplate → MyBatis(프레임워크) → JPA(모듈)
```

- MyBatis에서는 쿼리만 작성하면 된다.(RowMapper : X)

```java
SELECT * FROM member WHERE id = ?;
```

- JPA에서는 메서드를 작성해야 한다.

```java
findMemberMemberById(?);
```

## 왜 MyBatis와 JPA를 같이 쓰는지?

#### **JPA가 강한 영역**

- 엔티티 중심의 단순 CRUD (저장, 수정, 조회, 삭제)
- 객체 그래프 탐색, 연관관계 관리(1:N, N:M 등)를 자동으로 처리한다.
- 영속성 컨텍스트를 통한 변경 감지(dirty checking), 캐싱한다.
- 코드가 짧아지고 생산성이 높다.

#### **MyBatis가 강한 영역**

- 복잡한 통계 쿼리, 다중 조인, 동적 조건이 많은 리포트성 쿼리
- SQL을 직접 튜닝해야 하는 성능 민감 구간이다.
- 레거시 DB 스키마처럼 JPA 매핑이 까다로운 구조이다.
- "SQL을 내가 정확히 통제하고 싶다"는 요구가 강할 때

#### 단순 CRUD, 엔티티 관리 → JPA

#### 복잡한 조회/통계/레거시 쿼리 → MyBatis

## JPA → JPQL → QueryDSL

#### **JPA**

- 자바 진영의 ORM 표준 스펙(인터페이스 모음). 구현체로 Hibernate가 가장 많이 쓰인다.
- 엔티티를 객체처럼 다루면 SQL은 내부적으로 자동 생성된다.

#### **JPQL (Java Persistence Query Language)**

- JPA가 제공하는 객체지향 쿼리 언어.
- SELECT m FROM Member m WHERE m.age > 20 처럼 테이블이 아니라 엔티티/필드명 기준으로 작성한다.
- 문법은 SQL과 비슷하지만 대상이 엔티티라는 점이 다르다.
- 단점: 쿼리가 문자열이기 때문에 오타나 필드명 오류가 컴파일 타임에 안 잡히고 런타임에야 발견됨. 동적 쿼리(조건이 있을 때만 WHERE 추가 등) 작성이 지저분해진다.

#### **QueryDSL**

- JPQL을 코드(자바 메서드 체이닝)로 안전하게 작성할 수 있게 해주는 라이브러리.
- 컴파일 시점에 Q타입(QMember 등)을 자동 생성해서, 필드명 오타나 타입 오류를 컴파일 타임에 잡아준다.
- 동적 쿼리를 BooleanBuilder나 조건식으로 깔끔하게 조립 가능하다.
- 내부적으로는 결국 JPQL로 변환되어 실행된다.

#### MyBatis의 추가로 인한 방식의 변화

- 기존 방식: Controller → Service → DAO

```java
Controller → Service → DAO (구현 클래스) → SQL 직접 작성/JDBC 코드
```

- MyBatis 방식: Controller → Service → Mapper Interface → XML

```java
Controller → Service → MemberMapper (인터페이스) → MemberMapper.xml (SQL)
```

- MyBatis는 DAO의 역할을 인터페이스 + XML로 분리한다.

| 기존 DAO | MyBatis Mapper |
| --- | --- |
| 구현 클래스(직접 작성) | 인터페이스만 작성한다.(구현체는 MyBatis가 자동 생성) |
| SQL이 자바 코드 안에 문자열로 섞여 있다. | SQL이 XML로 완전히 분리되었다. |
| JDBC 코드(Connection 등)를 직접 관리한다. | MyBatis가 내부적으로 처리한다. |

| 애너테이션 | 역할 | XML 대응 |
| --- | --- | --- |
| @Select | 조회 | <select> |

| @Param | 파라미터 이름 지정(2개 이상일 때) | #{paramName} |

#### 관련 코드 예시 - MemberMapper.java(Interface)

```java
package com.office.calendar.member.mapper;

import com.office.calendar.member.MemberDto;
import org.apache.ibatis.annotations.*;
```
