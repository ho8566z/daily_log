-> JSTL(JavaServer Pages Standard Tag Library) 이란?


JSP에서 자주 사용하는 기능을 태그(Tag) 형태로 제공하는 표준 라이브러리이다.

JSP에서 Java 코드를 직접 작성하는 대신 JSTL 태그를 사용하여 조건문, 반복문, URL 처리 등의 기능을 구현할 수 있다.


JSTL 사용 방법

JSP에서 JSTL을 사용하려면 Tag Library를 선언해야 한다.

대표적인 Core 라이브러리는 다음과 같다.

<%@ taglib prefix="c"
    uri="http://java.sun.com/jsp/jstl/core" %>

이후 c라는 접두사를 사용하여 JSTL 태그를 사용할 수 있다.


JSTL의 주요 기능

1. 조건문 : <c:if>

조건에 따라 내용을 실행하거나 출력할 수 있다.

<c:if test="${member != null}">
    <p>회원 정보가 존재합니다.</p>
</c:if>


2. 반복문 : <c:forEach>

컬렉션이나 반복 데이터를 출력할 때 사용한다.

<c:forEach var="member" items="${members}">
    <p>${member.name}</p>
</c:forEach>


3. 변수 설정 : <c:set>

변수를 생성하거나 값을 설정할 때 사용한다.

<c:set var="name" value="홍길동" />

이후 EL을 사용하여 값을 출력할 수 있다.


JSTL과 EL의 관계

| 구분            | 역할                     |
| ------------- | ---------------------- |
| **JSTL**      | 조건문, 반복문 등의 기능 제공      |
| **EL**        | 객체나 변수에 저장된 값을 가져와 표현  |
| **JSP**       | HTML 화면 구성             |
| **Scriptlet** | JSP 내부에서 Java 코드 직접 작성 |

HTTP Method별 Mapping Annotation

Spring MVC에서 HTTP 요청 방식에 따라 사용하는 매핑 애너테이션은 @RequestMapping, @GetMapping, @PostMapping, @PutMapping, @PatchMapping, @DeleteMapping입니다.


1. @RequestMapping

@RequestMapping은 특정 URL 요청을 Controller의 메서드와 연결하는 애너테이션입니다.

@RequestMapping(
    value = "/createAccountConfirm",
    method = RequestMethod.POST
)
public String createAccountConfirm() {
    return "result";
}

method를 지정하지 않으면 여러 HTTP Method의 요청을 처리할 수 있습니다.


2. @GetMapping

GET 요청을 특정 Controller 메서드에 연결합니다.

@GetMapping("/member")
public String member() {
    return "member";
}

주로 데이터 조회, 페이지 요청 등에 사용합니다.


3. @PostMapping

POST 요청을 특정 Controller 메서드에 연결합니다.

@PostMapping("/member")
public String createMember(MemberDto memberDto) {
    return "result";
}

주로 데이터 생성이나 서버에 데이터를 제출할 때 사용합니다.


4. @PutMapping

PUT 요청을 특정 Controller 메서드에 연결합니다.

@PutMapping("/member")
public String updateMember(MemberDto memberDto) {
    return "result";
}

주로 기존 데이터를 수정/전체 교체할 때 사용합니다.


5. @PatchMapping

PATCH 요청을 특정 Controller 메서드에 연결합니다.

@PatchMapping("/member")
public String updateMember(MemberDto memberDto) {
    return "result";
}

주로 기존 데이터의 일부를 수정할 때 사용합니다.


6. @DeleteMapping

DELETE 요청을 특정 Controller 메서드에 연결합니다.

@DeleteMapping("/member")
public String deleteMember() {
    return "result";
}

주로 데이터 삭제에 사용합니다.


| 애너테이션             | HTTP Method | 주요 용도                  |
| ----------------- | ----------- | ---------------------- |
| `@RequestMapping` | 지정 가능       | URL과 Controller 메서드 연결 |
| `@GetMapping`     | GET         | 조회                     |
| `@PostMapping`    | POST        | 생성/데이터 제출              |
| `@PutMapping`     | PUT         | 수정/전체 교체               |
| `@PatchMapping`   | PATCH       | 부분 수정                  |
| `@DeleteMapping`  | DELETE      | 삭제                     |

JSP와 JavaScript의 실행 방식 차이

jsp 파일에서는 js코드를 입력할 수 있지만, js파일에 jsp 코드를 입력할 수 없기 때문에 jsp 파일에서 js코드를 입력해 이용한다.


JSP 파일에서는 JavaScript 코드를 작성하여 사용할 수 있지만, 일반적인 외부 JavaScript 파일(.js)에서는 JSP 코드가 서버에서 처리되지 않는다.

따라서 JSP의 서버 측 기능과 JavaScript의 클라이언트 측 기능을 함께 사용해야 하는 경우, JSP 파일에서 JavaScript 코드를 작성하거나 JSP에서 필요한 값을 JavaScript로 전달하는 방식을 사용한다.

JDBC와 Connection Pool

순수 JDBC
	-실무에서는 순수 JDBC 코드를 직접 사용하는 방식은 상대적으로 적게 사용된다.
		-DB 연결, SQL 실행, 예외 처리, 자원 해제 등의 코드를 반복적으로 작성해야 한다.
		-이러한 반복 작업을 줄이기 위해 JdbcTemplate, MyBatis, JPA 등의 기술을 사용한다.
	
Tomcat과 Application -(O)-> DB
Tomcat과 Application <-(X)- DB

	-애플리케이션이 필요할 때마다 매번 새로운 DB Connection을 생성하는 대신, Connection Pool이 여러 개의 Connection 객체를 미리 생성하거나 관리하고 있다가 필요할 때 제공한다.
	-작업이 끝난 Connection은 완전히 제거하는 것이 아니라 다시 Connection Pool로 반환하여 재사용할 수 있다.

[ jdbc-context.xml ]
-데이터베이스 연결 정보를 설정하고, Connection Pool 기능을 제공하는 DataSource 객체를 Spring Bean으로 등록하는 설정 파일

	<!-- connection bean(객체) -->
	<bean id="dataSource" class="org.apache.commons.dbcp2.BasicDataSource">
       <property name="driverClassName" value="com.mysql.cj.jdbc.Driver"/>
       <property name="url" value="jdbc:mysql://localhost:3306/db_library"/>
       <property name="username" value="root"/>
       <property name="password" value="1234"/>
   
       <!-- Connection Pool 설정 -->
       <property name="initialSize" value="5"/>
       <property name="maxTotal" value="10"/>
       <property name="maxIdle" value="2"/>
       <property name="minIdle" value="2"/>
   </bean>
   
   
dataSource 란?
	-DB Connection을 제공하고 관리하는 DataSource 객체의 Bean ID
   
BasicDataSource 란?
	-Apache Commons DBCP2가 제공하는 DataSource 구현체이다.
	-DriverManagerDataSource와 달리 Connection Pool 기능을 제공한다.


initialSize
	-<property name="initialSize" value="5"/>
	-애플리케이션이 시작될 때 처음 생성하는 Connection의 개수이다.

maxTotal
	-<property name="maxTotal" value="10"/>
	-Connection Pool에서 관리할 수 있는 최대 Connection 개수이다.
	-동시에 많은 요청이 발생해도 Connection은 최대 10개까지 생성·관리된다.

maxIdle
	-<property name="maxIdle" value="5"/>
	-사용하지 않고 Pool에 대기하는 Connection의 최대 개수이다.

minIdle
	-<property name="minIdle" value="2"/>
	-Pool에 대기 상태로 유지하려는 Connection의 최소 개수이다.
