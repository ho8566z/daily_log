#### Linux(Ubuntu)와 Docker를 이용한 앱 실행 순서

| 순서 및 할 일 | 어디서 / 무엇을 |  | 성공했을 때, 보이는 것 |  |
| --- | --- | --- | --- | --- |
| 1 WSL 켜기 | PowerShell에서 wsl |  | 이름@컴퓨터 : ~$ 프롬프트 |  |
| 2 Docker 확인 | Ubuntu에서 docker ps |  | 머리글 한 줄(오류 없음) |  |
| 3 DB 켜기 | Ubuntu에서 docker start shop-mysql |  | docker ps에 Up |  |
| 4 IntelliJ 열기 | 프로젝트 shop-project-5th (WSL 경로) |  | 아래 터미널이 Ubuntu |  |
| 5 앱 실행 | → (ShopApplication) 또는 ./gradlew bootRun |  | Started ShopApplication |  |
| 6 브라우저 확인 | localhost:8080/api/products |  | 상품 목록 JSON |  |

#### WSL 켜기 명령

- WSL 실행
    - powershell에 입력한다.
    - Windows에서 기본 Linux(Ubuntu 등)으로 진입한다.

```powershell
wsl
```

- 현재 사용자 확인
    - 현재 로그인한 Linux 사용자의 이름을 출력한다.

```powershell
whoami
```

- 현재 작업 디렉터리 확인
    - 현재 내가 위치한 폴더의 경로를 출력한다.

```powershell
pwd
```

#### Docker 확인 명령

- Docker 버전 확인
    - Docker가 설치되어 있는지와 설치된 버전을 확인한다.

```powershell
docker —version
```

- Docker 서비스 상태 확인

| active | Docker 서비스 실행 중이다. |
| --- | --- |
| inactive | Docker 서비스 중지 상태이다. |

```powershell
systemctl is-active docker
```

- 현재 실행 중인 컨테이너 확인
    - 실행 중인 컨테이너만 표시한다.

```powershell
docker ps
```

- 전체 컨테이너 확인
    - 실행 중인 컨테이너에 더해 중지된 컨테이너까지 표시한다.

```powershell
docker ps -a
```

#### DB 켜기 명령

- MySQL 컨테이너 실행
    - shop-mysql이라는 이름의 중지된 Docker 컨테이너를 다시 시작하고, 컨테이너가 실행되면 내부의 MySQL 서버도 함께 실행한다.

```powershell
docker start shop-mysql
```

#### 앱 실행 시 막히는 부분 목록

| 막힌 부분 | 증상 |  | 원인 |  | 해결 |  |
| --- | --- | --- | --- | --- | --- | --- |
| WSL | wsl이 인식되지 않는다.
창이 바로 닫힌다. |  | WSL 미설치거나 or 가상화 꺼져 있다. |  | WSL Install
Docker Install & Start |  |
| Docker | inactive / Cannot connect to be the Docker daemon |  | 엔진이 꺼져 있다. |  | sudo systemctl start docker |  |
| DB | docker ps 가 비어 있다. |  | 우분투가 꺼져서 멈췄다. |  | docker start shop-mysql |  |
| DB | port is already allocated |  | 3306을 다른 곳에서 사용한다. |  | docker ps 로 확인 후 그것을 stop한다. |  |
| 앱 | Communication link failure |  | DB가 안 떠 있다.
아직 준비 중이다. |  | DB Up 확인, 20~30초 확인 뒤 다시 실행한다. |  |
| 앱 | Post 8080 was already in use |  | 앱이 이미 떠 있다. |  | 기존 실행 중인 앱을 종료하거나 8080 포트를 사용하는 프로세스를 종료한 후 다시 실행한다. |  |

#### 회원과 상품의 CRUD 비교

| 구분 | 생성(Create/Insert) | 조회(Read/Select) | 수정(Update/Put) | 삭제(Delete) |
| --- | --- | --- | --- | --- |
| 회원 | join | login | me | logout |
| 상품 | create | findAll/findById | update | delete |

---

#### 하나의 서비스를 표현하는 클래스 구분

| 클래스 종류 | 어디서, 어디를 | 왜 구분하는지 |  |
| --- | --- | --- | --- |
| Product(Entity) | DB 서버 내부만 | 테이블 그대로 → id 자동 생성필드 포함 |  |
| ProductRequest | 클라이언트 → 서버 | 등록할 때 필요한 값만, id 없음 |  |
| ProductResponse | 서버 → 클라이언트 | 보여줄 값만, soldOut 같은 파생 필드 추가 |  |

#### Service 코드 예시

| 메서드 | 하는 일 |
| --- | --- |
| findAll(keyword) | 전체 조회, keyword 있으면 검색 |
| findById(id) | 상품 하나 조회 |
| create(request) | 새 상품 등록 |
| update(id, request) | 상품 정보 수정 |
| delete(id) | 상품 삭제 |

---

#### API와 메서드

| API | 메서드 |
| --- | --- |
| GET /api/products | findAll(keyword) 호출 |
| GET /api/products/{id} | findById(id) 호출 |
| POST /api/products | create(request) 호출 |
| PUT /api/products/{id} | update(id, request) 호출 |
| DELETE /api/products/{id} | delete(id) 호출 |

#### curl 명령어 예시

- docker가 start 중이고, IntelliJ에서 run되어서 server가 실행 중일때 InrelliJ의 Terminal에 입력한다.
- products : 블루투스 스피커를 추가하는 curl명령

```powershell
curl -X POST http://localhost:8080/api/products -H "Content-Type: application/json" -d'{"name":"블루투스 스피커", "price":45000, "stock":20, "description":"휴대용, 방수."}'
```
