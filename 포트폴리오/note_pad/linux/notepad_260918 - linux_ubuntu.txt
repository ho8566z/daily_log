#### 프로젝트 파일 / 디렉토리

| 파일/디렉토리 | 정체 |
| --- | --- |
| build.gradle | 프로젝트 구성과 실행에 필요한 것들 목록 |
| gradlew | 목록을 받아오는 역할 |
| gradle/wrapper/ | gradlew의 설정 |
| setting.gradle | 프로젝트 이름 |
| src/ | 작성했고, 작성하고, 작성할 코드의 위치 |
| .gitignore | git이 무시하거나 집중할 것들의 목록 |

## .gitignore 설정 방식: 블랙리스트 vs 화이트리스트

#### 1. 블랙리스트 방식 (제외할 것만 명시)

- 가장 일반적이고 흔하게 쓰는 방식이다.
- 무시할 파일/폴더를 하나씩 나열한다.
- 블랙리스트 예시

```
.log
*.class
node_modules/
target/
.env
.idea/
*.tmp
build/
```

| 패턴 | 의미 |
| --- | --- |
| *.log | 확장자가 .log인 모든 파일을 무시한다. |
| node_modules/ | 해당 폴더 전체를 무시한다. |
| .env | 특정 파일명을 무시 (환경변수, 민감정보) |
| build/, target/ | 빌드 결과물 폴더를 무시한다. |

#### 2. 화이트리스트 방식 (`!`로 예외 지정 — 허용할 것만 명시)

- ! 기호로 예외를 지정하는 방식이다.
- 프로젝트 구조가 복잡하거나 관리할 파일이 명확히 정해져 있을 때 사용한다.
- 화이트리스트 예시

```
1. 일단 모든 파일 무시
*

2. 특정 파일/폴더는 예외로 허용
!.gitignore
!src/
!src/**
!README.md
!pom.xml
```

| 패턴 | 의미 |
| --- | --- |
| * | 모든 파일을 일단 무시 대상으로 지정한다. |
| !src/ | src 폴더는 예외하고, 추적을 허용한다. |
| !src/** | src 폴더 내부의 모든 파일을 예외 처리한다.(주의: !src/만 쓰면 폴더는 보여도 내부 파일은 여전히 무시될 수 있음) |
| !.gitignore | .gitignore 파일 자체는 항상 추적되게 한다. |

#### 3. 주의할 점 — 화이트리스트 방식의 함정

- Git은 이미 무시된(ignored) 디렉토리 내부는 기본적으로 들여다보지 않는다.
- 그래서 아래처럼 작성하면 의도대로 동작하지 않을 수 있다.
- 해결 방법: 상위 폴더들도 하나씩 예외 처리해줘야 한다.

```
!src/
!src/main/
!src/main/java/
!src/main/java/**
```
