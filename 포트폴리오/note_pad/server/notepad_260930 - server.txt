#### Docker 란?

- 애플리케이션을 실행하는 데 필요한 환경을 하나의 컨테이너로 묶어서, 어디서든 동일하게 실행할 수 있도록 해주는 컨테이너 플랫폼이다.
- Docker를 사용하면 필요한 환경을 이미지(Image) 로 만들어 두고, 그 이미지를 기반으로 컨테이너(Container) 를 실행할 수 있다.

#### DockerHub 란?

- Docker Image를 저장하고 공유할 수 있는 온라인 저장소(Registry)이다.

#### Docker와 DockerHub의 관계

| 구분 | 내용 |  |
| --- | --- | --- |
| **Docker** | 애플리케이션을 실행하는 데 필요한 환경의 묶음 |  |
| **DockerHub** | Docker Image를 저장하고 공유할 수 있는 공간 |  |

---

#### WAS(Web Application Server) 란?

- 웹 애플리케이션을 실행하고, 클라이언트의 요청을 받아 애플리케이션의 로직을 처리하는 서버이다.
- 서버 프로그램을 WAS라고 하며, Tomcat은 대표적인 WAS 중 하나이다.

#### L4장비 란?

- 네트워크의 4계층(Transport Layer) 정보를 기준으로 트래픽을 분산해 주는 장비이다.

```
                    사용자
                      │
                  HTTP 요청
                      ↓
                ┌──────────┐
                │ L4 장비  │
                │ 로드밸런서 │
                └────┬─────┘
                     │
             ┌───────┴───────┐
             ↓               ↓
        ┌─────────┐      ┌─────────┐
        │ Server 1│      │ Server 2│
        └─────────┘      └─────────┘
```

#### 왜 L4인가?

- OSI 7계층에서 L4 = 전송 계층(Transport Layer)이다.
- L4 장비는 주로 다음과 같은 정보를 이용한다.
    - IP 주소
    - TCP / UDP
    - Port 번호
- L4 장비가 요청을 여러 서버로 분산시키는 것을 로드 밸런싱(Load Balancing)이라고 한다.

## VirtualBox Server 복제 및 복원

#### 1. Server 복제

!image.png

!image.png

!image.png

- 기존 Server VM을 그대로 복사하여 새로운 Server VM을 생성한다.

```powershell
VirtualBox → Server 선택 → 복제(Clone)
```

- 복제 과정에서 새로운 VM의 이름과 설정을 지정한다.
- 원본 Server를 보존한 상태에서 동일한 환경의 Server를 하나 더 만들 수 있다.

---

#### 2. 복제 후 작업

- 복제된 Server에서 필요한 설치 및 설정 작업을 진행한다.

```
원본 Server
    ↓
   복제
    ↓
복제된 Server
    ↓
설정 및 작업
```

---

#### 3. 문제 발생 시 복원

- 복제된 Server에서 작업하다가 문제가 발생하면 기존에 보존해 둔 원본 Server 또는 Snapshot을 이용하여 이전 상태로 되돌린다.

```
원본 Server
    │
    ├── Clone ──→ 복제 Server
    │                │
    │                └── 작업
    │                     ↓
    │                   문제 발생
    │                     ↓
    └──────────────→ 이전 상태로 복원
```

---

#### 4. Clone과 Snapshot의 차이

| 구분 | Clone | Snapshot |
| --- | --- | --- |
| 목적 | VM 자체를 복사 | 특정 시점의 상태 저장 |
| 결과 | 새로운 VM 생성 | 기존 VM에 복원 지점 생성 |
| 독립 실행 | 가능 | 기존 VM에서 사용 |
| 복원 | 직접 원본/복제본으로 전환 | 저장된 시점으로 되돌림 |
| 활용 | 서버 환경 복제 | 작업 전 백업 및 롤백 |

## VirtualBox — Linux(Ubuntu) Install, Update

#### 1. Ubuntu 기본 설정

- VirtualBox에 Ubuntu를 설치한 후, 개발 환경을 구축하기 전에 패키지 목록과 설치된 패키지를 최신 상태로 업데이트한다.

#### 패키지 목록 업데이트

```bash
sudo apt update
```

- 설치할 수 있는 패키지 목록을 최신 정보로 갱신

---

#### 2. Git, JDK 설치

- Ubuntu에서 Java 기반 개발 환경을 사용하기 위해 Git과 JDK를 설치한다.

#### Git 설치

```bash
sudo apt install git
```

- Git : 소스 코드 버전 관리

#### JDK 설치

```bash
sudo apt install openjdk-17-jdk
```

- JDK(Java Development Kit) : Java 프로그램을 개발하고 컴파일하기 위한 개발 도구

#### 설치 확인

```bash
git --version
java -version
javac -version
```

- java : Java 프로그램 실행
- javac : Java 소스 코드 컴파일

---

#### 3. Gradle 설치

- Gradle은 Java 프로젝트의 빌드 및 의존성 관리를 담당하는 빌드 도구이다.
- Ubuntu의 apt를 이용해 설치할 수도 있지만, 특정 버전을 사용해야 하는 경우에는 Gradle 배포 파일을 직접 다운로드하여 설치할 수 있다.

#### 3-1. Gradle 다운로드

```bash
wget https://services.gradle.org/distributions/gradle-8.10.2-bin.zip -P /tmp
```

- wget : 인터넷에서 파일을 다운로드하는 명령어
- P /tmp : /tmp 디렉터리에 다운로드

---

#### 3-2. Gradle 압축 해제

```bash
sudo unzip -d /opt/gradle /tmp/gradle-8.10.2-bin.zip
```

- unzip : ZIP 압축 파일 해제
- d /opt/gradle : /opt/gradle에 압축 해제
- /opt : 시스템에서 별도의 소프트웨어를 설치할 때 사용하는 대표적인 위치

```
/opt/
└── gradle/
    └── gradle-8.10.2/
        ├── bin/
        ├── lib/
        └── ...
```

---

#### 4. 환경변수 설정

- Java와 Gradle을 어느 디렉터리에서든 명령어로 실행할 수 있도록 환경변수를 설정한다.
- 사용자 환경변수는 ~/.profile에 설정할 수 있다.

#### .profile 수정

```bash
nano ~/.profile
```

- 다음과 같이 환경변수를 추가한다.

```bash
export JAVA_HOME=/usr/lib/jvm/java-17-openjdk-amd64
export GRADLE_HOME=/opt/gradle/gradle-8.10.2
export PATH=$JAVA_HOME/bin:$GRADLE_HOME/bin:$PATH
```

#### 환경변수 의미

| 환경변수 | 의미 |
| --- | --- |
| JAVA_HOME | JDK가 설치된 위치 |
| GRADLE_HOME | Gradle이 설치된 위치 |
| PATH | 명령어를 검색할 디렉터리 목록 |
- 특히 PATH에 다음 경로를 추가하면 어느 위치에서든 명령어를 실행할 수 있다.

```
$JAVA_HOME/bin
$GRADLE_HOME/bin
```

---

#### 5. 변경된 환경변수 적용

- .profile을 수정한 후에는 현재 터미널에 변경 내용을 적용한다.

```bash
source ~/.profile
```
