## DHCP 란?

- DHCP(Dynamic Host Configuration Protocol)는 네트워크에 접속한 장치에 IP 주소 등 네트워크 설정을 자동으로 할당해 주는 프로토콜이다.
- 사용자가 IP, 서브넷 마스크, 게이트웨이, DNS를 직접 입력하지 않아도 통신할 수 있다.

#### DHCP가 할당하는 정보

| 구분 | 내용 |
| --- | --- |
| IP 주소 | 장치가 사용할 주소 |
| 서브넷 마스크 | 네트워크 범위 구분 |
| 게이트웨이 | 외부 네트워크로 나가는 출입구 |
| DNS 서버 | 도메인 이름을 IP로 변환 |

#### 서버에서 주의할 점

- DHCP는 IP가 바뀔 수 있으므로, 서버는 보통 고정 IP를 사용한다.

## FTP 란?

- FTP(File Transfer Protocol)는 클라이언트와 서버 사이에서 파일을 주고받기 위한 프로토콜이다.
- 기본적으로 21번 포트를 사용한다.
- 서버에 파일을 업로드하거나 서버의 파일을 다운로드할 때 쓴다.

```
클라이언트(FileZilla)  ← FTP(21) →  FTP 서버(vsFTPd)
  업로드 / 다운로드                     파일 저장
```

---

## vsFTPd 란?

- vsFTPd(Very Secure FTP Daemon)는 리눅스에서 많이 쓰는 FTP 서버 프로그램이다.
- 이름처럼 보안과 안정성에 초점을 둔 가벼운 FTP 서버다.

#### vsFTPd 설치

```powershell
sudo apt-get update
sudo apt-get install vsftpd
```

- apt-get : Ubuntu/Debian 계열 Linux에서 패키지를 관리하는 명령어이다.
- update를 먼저 실행해 패키지 목록을 최신화한 뒤 설치하는 것이 안전하다.

#### vsFTPd 상태 확인

```powershell
sudo systemctl status vsftpd
```

- systemctl status : 서비스의 실행 상태를 확인한다.
- active (running)이 보이면 정상 실행 중이다.

#### vsFTPd 설정 편집

```powershell
sudo nano /etc/vsftpd.conf
```

- 주석(#)을 해제하거나 값을 수정해서 아래 항목을 설정한다.
- nano에서 저장 : Ctrl+X → Y → Enter

| 설정 항목 | 의미 |  |
| --- | --- | --- |
| anonymous_enable=NO | 익명 사용자의 FTP 접속을 막아 보안을 강화한다. |  |
| write_enable=YES | FTP 서버에서 파일 업로드 및 수정 등의 쓰기 작업을 허용한다. |  |
| xferlog_file=/var/log/vsftpd.log | FTP 서버에서 발생한 파일 전송 로그를 /var/log/vsftpd.log에 기록한다. |  |

#### vsFTPd 재시작

```powershell
sudo systemctl restart vsftpd
```

- 설정 파일을 수정한 뒤에는 재시작해야 변경 내용이 적용된다.
- 재시작 후 status로 active (running)인지 다시 확인한다.

## FileZilla 란?

- FileZilla는 FTP 서버에 접속해서 파일을 주고받는 무료 FTP 클라이언트 프로그램이다.
- 공식 웹사이트 : https://filezilla-project.org/
- 설치 시 주의 : 설치 과정에 끼어 있는 광고성 프로그램 설치 옵션은 거절(Decline)한다.
- 연결 순서 : 사이트 관리자 → 새 사이트 → Ubuntu IP와 계정 입력 → 연결
- 한글 파일명이 깨지면 사이트 설정의 문자셋을 UTF-8 강제 사용으로 바꾸고 다시 연결한다.

## Docker로 Spring 앱 배포하기

#### 배포 흐름

```
개발 PC → GitHub(소스) → 빌드 서버(빌드 + 이미지 생성) → Docker Hub(이미지 저장) → 실행 서버(pull + run)
```

- 실행 서버에는 Docker만 있으면 되고, JDK·Gradle·Git은 필요 없다.

---

#### 1. build.gradle 설정

```
jar {
    enabled = false
}
```

- 일반 jar(xxx-plain.jar)가 같이 만들어지는 것을 막는다.(실행 가능한 bootJar는 그대로 생성된다.)
- build/libs에 jar가 하나만 남아야 Dockerfile의 COPY 경로를 헷갈리지 않는다.

---

#### 2. Docker 설치 (Ubuntu)

```powershell
sudo apt-get update
sudo apt-get install ca-certificates curl
sudo install -m 0755 -d /etc/apt/keyrings
sudo curl -fsSL https://download.docker.com/linux/ubuntu/gpg -o /etc/apt/keyrings/docker.asc
echo "deb [arch=$(dpkg --print-architecture) signed-by=/etc/apt/keyrings/docker.asc] https://download.docker.com/linux/ubuntu $(. /etc/os-release && echo $VERSION_CODENAME) stable" | sudo tee /etc/apt/sources.list.d/docker.list
sudo apt-get update
sudo apt-get install docker-ce
docker --version
```

- Ubuntu 기본 저장소가 아니라 Docker 공식 저장소에서 설치하므로, 저장소와 인증 키를 먼저 등록한다.
- docker --version으로 설치 여부를 확인한다.

---

#### 3. Dockerfile 작성(명령어 설명)

```docker
FROM bellsoft/liderica-openjdk-alpine:17

CMD ["./gradlew", "clean", "build"]

VOULUME /tmp

ARG JAR_FILE=build/libs/*.jar

COPY ${JAR_FILE} app.jar

EXPOSE 8090

ENTRYPOINT ["java", "-jar", "/app.jar"]
```

| 명령어 | 의미 |
| --- | --- |
| FROM bellsoft/liberica-openjdk-alpine:17 | 베이스 이미지 지정. Alpine Linux 기반의 JDK 17 이미지를 사용합니다. |
| CMD [...] | 컨테이너 시작 시 기본으로 실행할 명령 또는 인자를 지정합니다. |
| VOLUME /tmp | /tmp를 볼륨으로 선언합니다. 스프링 부트 내장 톰캣이 /tmp에 임시 파일을 쓰기 때문에 넣는 관례입니다. |
| ARG JAR_FILE=build/libs/*.jar | 빌드 시점 변수입니다. Gradle이 만든 jar 경로의 기본값이며, --build-arg로 덮어쓸 수 있습니다. |
| COPY ${JAR_FILE} app.jar | 호스트의 jar를 이미지 안에 app.jar로 복사합니다. |
| EXPOSE 8090 | 컨테이너가 8090 포트를 쓴다는 문서화용 선언입니다. 실제 포트 오픈은 docker run -p로 해야 합니다. |
| ENTRYPOINT [...] | 컨테이너 시작 시 실행할 고정 명령입니다. java -jar /app.jar로 앱을 실행합니다. |

---

#### 4. 이미지 빌드와 Docker Hub 업로드(빌드 서버)

```powershell
sudo docker build -t [계정]/samplepjt:1.0 .
sudo docker images
sudo docker login -u [계정]
sudo docker push [계정]/samplepjt:1.0
```

- build -t : 이미지에 [계정]/[이름]:[태그] 이름을 붙인다. 마지막 .은 Dockerfile이 있는 현재 폴더를 뜻한다.
- images : 만들어진 이미지 목록 확인
- login / push : Docker Hub에 로그인한 뒤 이미지를 올린다. 이미지 이름의 계정이 로그인한 계정과 같아야 push가 된다.

---

#### 5. 이미지 내려받기와 실행(실행 서버)

```powershell
sudo docker login -u [계정]
sudo docker pull [계정]/samplepjt:1.0
sudo docker images
sudo docker run --name spring -d -p 8090:8090 [계정]/samplepjt:1.0
```

| 옵션 | 의미 |  |  |
| --- | --- | --- | --- |
| --name spring | 컨테이너 이름을 spring으로 지정한다. |  |  |
| -d | 백그라운드로 실행한다. |  |  |
| -p 8090:8090 | [서버 포트]:[컨테이너 포트]를 연결한다. 이 설정이 있어야 밖에서 접속할 수 있다. |  |  |
- 공개 이미지라면 login 없이 pull 할 수 있다.

---

#### 6. 컨테이너 관리 명령어

| 명령어 | 설명 |  |
| --- | --- | --- |
| sudo docker ps | 실행 중인 컨테이너 목록 |  |
| sudo docker ps -a | 중지된 것을 포함한 전체 컨테이너 목록 |  |
| sudo docker stop spring | 컨테이너 중지 |  |
| sudo docker start spring | 중지된 컨테이너 다시 시작 |  |
| sudo docker rm spring | 컨테이너 삭제 (실행 중이면 먼저 stop) |  |
| sudo docker logs spring | 앱 로그 확인 (실행이 안 될 때 가장 먼저 본다.) |  |
- 컨테이너를 삭제해도 이미지는 남는다.
- 이미지 삭제명령어는 “docker rmi” 이다.

## 활용 : FTP와의 연결

- FTP(FileZilla)는 호스트의 /upload 같은 디렉터리를 직접 확인하거나 파일을 옮길 때 는 통로가 된다.
- 서버를 고정 IP로 두면 FileZilla 사이트 설정을 매번 고치지 않아도 된다.
- 방화벽(ufw)을 켜 둔 서버라면 21번 포트를 허용해야 접속된다.
- FTP는 아이디와 비밀번호가 암호화되지 않고 전송되므로 실습·내부망용으로만 쓴다.
