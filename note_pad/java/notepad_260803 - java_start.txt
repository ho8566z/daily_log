Java

Java는 객체지향(Object-Oriented) 프로그래밍 언어이자 플랫폼으로, 한 번 작성한 프로그램을 다양한 운영체제에서 실행할 수 있도록 설계된 언어입니다.

------------------------------------------------------------------------
Java란?

Java는 1995년 **Sun Microsystems**에서 개발되었으며, 현재는 **Oracle**이 개발과 유지보수를 담당하고 있습니다.

------------------------------------------------------------------------
Java의 가장 큰 특징은
"Write Once, Run Anywhere(WORA)"
한 번 작성하면 어디서나 실행할 수 있다.
입니다.
이는 JVM(Java Virtual Machine) 덕분에 가능합니다.

------------------------------------------------------------------------
Java의 탄생 배경

1990년대에는 운영체제마다 사용하는 언어와 실행 방식이 달랐습니다.
이를 해결하기 위해 Java는
Java 코드
↓
바이트코드(.class)
↓
JVM
↓
각 운영체제에서 실행
이라는 구조를 만들었습니다.
운영체제마다 JVM만 설치되어 있다면 같은 Java 프로그램을 실행할 수 있습니다.

------------------------------------------------------------------------
Java 프로그램의 실행 과정

개발자
↓
Main.java 작성
↓
JDK의 javac 컴파일러
↓
Main.class (바이트코드)
↓
JRE
↓
JVM
↓
운영체제(Windows, Linux, macOS)
↓
프로그램 실행
즉,
Java는 운영체제가 아니라 JVM 위에서 실행되는 언어입니다.

------------------------------------------------------------------------
Java의 특징

1. 객체지향 프로그래밍(OOP)
Java는 객체(Object)를 중심으로 프로그램을 작성합니다.
현실 세계의 사물을 객체로 표현합니다.

------------------------------------------------------------------------
2. 플랫폼 독립성

Java는 운영체제에 종속되지 않습니다.
Main.class
↓
Windows JVM
↓
실행
--------------------
Main.class
↓
Linux JVM
↓
실행
--------------------
Main.class
↓
macOS JVM
↓
실행
같은 .class 파일을 그대로 사용할 수 있습니다.

------------------------------------------------------------------------
3. 자동 메모리 관리(Garbage Collection)

C/C++에서는 메모리를 직접 해제해야 합니다.
Java는 객체를 더 이상 사용하지 않으면 JVM의 Garbage Collector(GC) 가 자동으로 메모리를 회수합니다.

------------------------------------------------------------------------
4. 높은 안정성

Java는 실행 중 발생하는 다양한 오류를 예외(Exception) 처리로 관리할 수 있습니다.
프로그램이 비정상 종료되는 상황을 줄이고, 오류를 적절히 처리할 수 있습니다.

------------------------------------------------------------------------
Java의 장점

운영체제와 관계없이 실행 가능
객체지향 프로그래밍 지원
자동 메모리 관리(GC)
높은 보안성과 안정성
풍부한 표준 라이브러리
대규모 프로젝트에 적합
기업에서 많이 사용하는 언어

------------------------------------------------------------------------
Java의 단점

JVM을 거치므로 C/C++보다 실행 속도가 느릴 수 있음
메모리 사용량이 비교적 많음
문법이 다소 길고 엄격함

------------------------------------------------------------------------
Java의 활용 분야
Java는 다양한 분야에서 사용됩니다.

분야	활용 예시
웹 개발	Spring, Spring Boot

서버 개발	금융 시스템, 쇼핑몰, ERP
기업 시스템	그룹웨어, 인사관리, 회계 시스템
빅데이터	Apache Hadoop, Apache Spark
클라우드	마이크로서비스, REST API

------------------------------------------------------------------------
Java의 핵심 구성 요소
Java 개발
↓
JDK
(개발 도구)
↓
JRE
(실행 환경)
↓
JVM
(실행 엔진)
↓
운영체제

JDK: Java 프로그램을 개발(컴파일·디버깅)하는 도구 모음
JRE: Java 프로그램을 실행하기 위한 환경
JVM: 바이트코드를 실제로 실행하는 가상 머신

------------------------------------------------------------------------
------------------------------------------------------------------------
1. JVM (Java Virtual Machine)

JVM은 Java 프로그램을 실제로 실행하는 가상 머신입니다.

JVM의 역할
바이트코드 실행
메모리 관리
Garbage Collection(GC)
운영체제 차이 숨김

즉,
"Java 프로그램을 실행하는 엔진"
입니다.

------------------------------------------------------------------------
2. JRE (Java Runtime Environment)

JRE는 Java 프로그램을 실행하기 위한 환경입니다.

JRE 안에는
JVM
Java 실행에 필요한 라이브러리(API)
가 들어 있습니다.

즉,
"실행에 필요한 모든 것"
입니다.

하지만
JRE만 있으면
javac Main.java
같은 컴파일은 할 수 없습니다.
실행만 가능합니다.

------------------------------------------------------------------------
3. JDK (Java Development Kit)

JDK는 Java 개발 도구 모음입니다.

안에는
JRE
컴파일러(javac)
디버거
각종 개발 도구
가 포함됩니다.

대표적인 명령어
javac Main.java
컴파일
java Main
실행
둘 다 JDK에 포함되어 있습니다.

------------------------------------------------------------------------
JDK, JRE, JVM의 포함 관계
JDK
│
├── javac
├── jar
├── javadoc
├── jdb
├── java
│
└── JRE
      │
      ├── JVM
      │
      ├── Java API
      │
      └── 실행 라이브러리
즉,
JVM은 프로그램을 실행하는 엔진
JRE는 JVM과 실행에 필요한 라이브러리를 포함한 실행 환경
JDK는 JRE에 컴파일러와 디버거 등 개발 도구를 추가한 개발 환경

Java를 설치한 후 환경 변수(Environment Variables) 를 설정하는 이유는 어느 폴더에서든 Java 명령어(java, javac)를 사용할 수 있도록 하기 위해서입니다.

환경 변수(Environment Variables)란?
환경 변수는 운영체제(Windows)가 프로그램의 위치나 설정 정보를 저장해 두는 변수입니다.

Java 환경 변수의 종류

Java에서는 주로 두 가지를 설정합니다.
JAVA_HOME
PATH

1. JAVA_HOME
JAVA_HOME은
JDK가 설치된 위치를 저장하는 환경 변수
입니다.

예를 들어
JAVA_HOME
↓
C:\Program Files\Java\jdk-21
처럼 설정합니다.

주의할 점은 bin까지 포함하지 않는 것입니다.

------------------------------------------------------------------------
JAVA_HOME을 사용하는 이유
많은 개발 도구들이 Java의 설치 위치를 자동으로 찾기 위해 JAVA_HOME을 사용합니다.

예를 들어
IntelliJ IDEA
Eclipse
Apache Maven
Gradle
Apache Tomcat
등이 JAVA_HOME을 참조합니다.

------------------------------------------------------------------------
2. PATH

PATH는
Windows가 실행 파일을 찾는 경로 목록
입니다.

예를 들어
PATH
↓
C:\Windows\System32
↓
C:\Program Files\Java\jdk-21\bin
↓
...
처럼 여러 경로가 등록되어 있습니다.

Java를 추가할 때는 보통
%JAVA_HOME%\bin
을 PATH에 등록합니다.

------------------------------------------------------------------------
왜 %JAVA_HOME%\bin을 사용할까?

예를 들어
직접 등록하면
C:\Program Files\Java\jdk-21\bin
이 됩니다.

나중에 Java 25를 설치하면
C:\Program Files\Java\jdk-25\bin
으로 다시 수정해야 합니다.

반면
JAVA_HOME
↓
C:\Program Files\Java\jdk-25
만 변경하면
PATH
↓
%JAVA_HOME%\bin
은 자동으로
C:\Program Files\Java\jdk-25\bin
을 가리키게 됩니다.
즉, 유지보수가 쉬워집니다.

------------------------------------------------------------------------
환경 변수 확인

명령 프롬프트(cmd)에서
Java 버전 확인
java -version
예시
java version "21.0.8"

컴파일러 확인
javac -version
예시
javac 21.0.8

src를 마우스 오른쪽 클릭

src

src
└── com
    └── apple
        └── first
