1. 객체지향 프로그램

1-1. 객체지향 프로그램의 개념

객체를 사용하는 것을 의미한다.

즉, 데이터와 메서드를 포함하는 '객체'개념에 기반한 프로그래밍

주요목적은 프로그램의 유연성(부품화)을 향상하고 유지, 관리의 가능성을 높이는 것이다.

장점
	개발 속도 향상
	소프트웨어 유지관리 향상 <- 강조
	소프트웨어 개발의 생산성 향상 <- 강조
	개발 비용 절감
	
객체지향 프로그램의 구성요소
	클래스(class)			같은 종류의 집단에 속한 속성과 행동을 정의한 틀이다.
	객체(object)				클래스의 인스턴스이다.
	캡슐화(encapsulation)	데이터와 행동을 하나의 단위로 묶는 기법이다.
	상속(inheritance)		이미 존재하는 한 클래스의 멤버(변수, 메서드)를 다른 클래스에 물려주는 기법이다.
	다향성(polymorphism)		변수, 메서드 또는 객체가 여러 행태를 취하는 기법이다.
	추상화(abstraction)		불필요한 내부 세부 사항을 숨기고, 필수 사항을 표시하는 것을 의미한다.


1-2. 캡슐화

캡슐화는 데이터(변수)와 행동(메서드)을 하나의 단위(클래스)로 묶는 기법이다.

즉, 데이터를 수정하지 못하도록 안전하게 하기 위해 정보의 세부 사항을 숨기고, 객체의 데이터와 메서드를 보호하는 과정이다.

캡슐화 <- 이미지 만들기 : [ 클래스 -> 캡슐(변수 / 메서드) ]


1-3. 상속

이미 존재하는 한 클래스의 멤버(변수, 메서드)를 다른 클래스에 물려주는 기법이다.

코드를 재사용하고 두 클래스 간에 부모-자식 관계를 설정하는 데 도움이 된다.

상속의 구성요소
	부모 클래스 : 상위 클래스, 슈퍼 클래스, 기본 클래스
	자식 클래스 : 하위 클래스, 서브 클래스, 파생 클래스
	
	
1-4. 다향성

여러 형태를 취한다는 의미로, 객체지향 프로그래밍에서 변수, 메서드, 객체가 여러 형태를 취하는 기법이다.

상속에 의해 서로 관련된 하나 이상의 클래스 또는 객체가 있을 때, 다향성이 발생한다.


-메서드 오버로딩

메서드명이 같지만 메서드레 전달된 매개변수의 자료형 또는 개수가 다른 둘 이상의 메서드를 갖는 것을 의미한다.

컴파일타임 다형성의 예시


-메서드 오버라이딩

상위 클래스의 메서드를 하위 클래스에서 재정의하는 것을 의미한다.

런타임 다형성의 예시


1-5. 추상화

불필요한 세부 정보를 포함하지 않고 객체의 공통적인 속성과 행동만을 나타내는 것을 의미한다.

주요목적은 불필요한 세부 정보를 숨겨서 프로그래밍의 복잡성과 노력을 줄이는 데 있다.



2. 클래스와 객체

2-1. 클래스와 객체의 관계

객체지향 프로그래밍은 객체를 조립해 프로그램을 만드는 것이다.

객체지향 프로그램의 설계도를 클래스라고 한다.

클래스는 객체를 만들기 위한 템플릿이다.


2-2. 클래스 설계 및 구현

클래스는 객체가 어떻게 작동하고 객체가 무엇을 할 것인지를 결정한다.

즉, 객체에 어떤 속성(Attribute / 상태)이 있고, 어떤 기능(Method / 행동)을 하는지를 설명하는 설계도이다.


-클래스 설계

속성은 클래스에 대한 데이터라고 볼 수 있다.

행동은 클래스에 대한 메서드라고 볼 수 있다.


-클래스 구현

클래스를 구현할 때는 class 키워드를 사용하고 클래스의 본문을 중괄호({})로 묶는다.

클래스의 구성 요소는 변수(속성), 메서드(기능) 등이며, 클래스를 구현하는 일반적인 형식은 다음과 같다.

[접근제한자] class 클래스명 { <- 이미지 만들기
	(멤버)변수	<- 속성
	(멤버)메서드	<- 행동
}

모든 클래스에 변수(데이터)와 메서드가 있는 것은 아니며, 변수만 포함된 클래스도 있고, 메서드만 포함된 클래스도 있다.

클래스가 수행해야 하는 작업에 따라 멤버 구성 요소를 다르게 선언한다.

2-3. 객체

객체는 클래스의 인스턴스이다.

객체는 클래스 자체의 복사본으로, 특정 유형의 데이터를 유용하게 만드는 메서드와 변수(속성)로 구성된다.


-객체 생성

클래스를 통해 객체를 생성하려면 new 키워드를 사용하며 형식은 다음과 같다.

클래스명 객체명 = new 클래스명(); <- 이미지 만들기
	Cat catObj = new Cat();
(클래스명 : 데이터타입 / 객체명 : 변수명 / new : 객체 생성자)

3. 클래스의 구성 요소

클래스의 구성 요소는 실세계에서의 속성과 행동에 행동하는 변수, 메서드, 클래스명과 같은 생성자이다.

-멤버 변수 : 객체의 데이터가 저장되는 곳

-멤버 메서드 : 객체의 동작, 데이터의 조작이 이루어지는 곳

-생성자 : 객체를 생성할 때 초기화되는 항목 관리


3-1. 멤버 변수

데이터를 저장할 수 있는 메모리 공간은 변수이다.

변수는 실제로 클래스의 속성이며, 이러한 클래스의 속성을 클래스 내의 멤버 변수 또는 필드(field)라고 부른다.

멤버 변수는 객체의 데이터, 메서드의 반환값, 상태 등을 저장하는 곳을 의미한다.

변수는 생성자와 메서드 내에서만 사용하고 생성자와 메서드가 종료되면 같이 소멸되지만, 멤버 변수는 객체가 소멸되어야 같이 소멸된다.

자료형 멤버변수명 = 초기값;	<- 생략 가능


-멤버 변수 접근

클래스 내의 멤버 변수는 객체를 만들고 마침표(.) 구문을 사용하여 접근할 수 있다.

3-2. 멤버 메서드

메서드는 클래스 내에서 선언되고 특정 작업을 수행하는데 사용되었다.

메서드는 선언부와 중괄호 안의 구현부로 구성되며, 호출되면 중괄호 안의 모든 내용이 순차적으로 실행된다.

메서드의 구분
	정적 메서드(static method)
		static 키워드를 선언하는 메서드
		객체를 생성하지 않고 바로 사용한다.
	
	인스턴스 메서드(instance method)
		static 키워드를 선언하지 않는 메서드
		객체를 생성해야만 사용할 수 있다.

4. 생성자

객체를 생성할 때 new 연산자를 사용하며 호출되는 부분으로 클래스의 객체가 생성될 때마다 자동으로 호출되고 객체를 초기화하는 데 이용되는 특수한 유형의 메서드이다.

생성자명은 해당 클래스명과 동일해야 한다.


4-1. 기본 생성자(default constructor)

기본 생성자는 매개변수가 없는 생성자로, 클래스 내에 기본 생성자를 정의하지 않아도 된다.

클래스 내에 기본 생성자를 정의하지 않으면 컴파일러는 해당 클래스에 대한 기본 생성자를 자동으로 생성한다.
