## 비동기 방식 이란?

- 웹 개발에서 비동기(Asynchronous) 방식은 요청을 보낸 후 응답을 기다리지 않고 다른 작업을 계속 수행할 수 있도록 하는 방식이다.
- 웹 브라우저(프론트엔드) 환경에서 비동기 코드는 주로 JavaScript로 작성한다.
- 비동기의 반대는 동기(Synchronous) 방식이다.
- 동기 방식이란?
    - 요청을 보낸 후, 응답이 올 때까지 다음 코드를 실행하지 않고 대기(block)하는 방식이다.
    - 작업이 순서대로(순차적으로) 처리되기 때문에 코드 흐름을 이해하기 쉽지만, 응답이 오래 걸리는 작업이 있으면 그 뒤의 작업들도 전부 지연된다.

| 비동기(Asynchronous) | 동기(Synchronous) |
| --- | --- |
| 클라이언트는 서버로 요청을 보낸 후 응답을 기다리지 않고 다음 작업을 진행한다. | 클라이언트는 서버로 요청을 보낸 후 응답이 올 때까지 기다린 후 다음 작업을 진행한다. |

#### 비동기 방식의 장점

- UI 블로킹 방지 (클라이언트 성능 향상)
    - 클라이언트는 요청을 보내고 서버의 응답을 기다리지 않고 다른 작업(화면 렌더링, 사용자 입력 처리 등)을 계속할 수 있다.
- 빠른 사용자 경험
    - 응답을 기다리는 동안에도 화면이 멈추지 않고 다른 UI 요소(버튼 클릭, 스크롤 등)가 정상적으로 동작하기 때문에, 사용자는 웹페이지가 느리다고 느끼지 않는다.
- 병렬 처리 가능
    - 여러 개의 요청을 동시에 보내고 각각의 응답을 별도로 처리할 수 있다.
    - 예를 들어 이미지 3개를 동시에 요청하면, 하나씩 순서대로 기다리는 것보다 훨씬 빠르게 전체 작업을 끝낼 수 있다.

## REST API 이란?

- REST(REpresentational State Transfer)는 웹에서 시스템 간에 데이터를 주고받기 위한 아키텍처 스타일(설계 원칙)이다.
- 이 원칙을 따르는 API를 REST API라고 한다.

## 1. REST API 종류

#### 1-1. AJAX (Asynchronous JavaScript and XML)

- 특정한 라이브러리나 모듈이 아니라, 비동기적으로 데이터를 주고받는 기술을 의미한다.
- 예전에는 XMLHttpRequest 객체를 사용해 AJAX 요청을 보냈지만, 요즘은 Fetch나 Axios로 대체되었다.
- XMLHttpRequest 이란?
    - 브라우저에서 서버와 비동기(또는 동기)로 데이터를 주고받을 수 있게 해주는 내장 객체(Built-in Object)다.
    - AJAX 통신의 원조 격 기술로, 자바스크립트 초기부터 지원되었다.
    - 사용법이 다소 복잡하고 콜백 기반이라 코드가 길어지는 단점이 있다.
- $.ajax() 이란?
    - jQuery 라이브러리에서 제공하는 AJAX 요청 함수다.
    - XMLHttpRequest를 내부적으로 감싸서(wrapping), 더 간단한 문법으로 비동기 요청을 보낼 수 있게 해준다.
    - 과거 jQuery가 널리 쓰이던 시절 AJAX 통신의 표준처럼 사용되었지만, 요즘은 Fetch API나 Axios로 대체되는 추세다.

#### 1-2. Fetch API

- JavaScript 기본 내장 기능으로 fetch() 함수를 사용해서 요청을 보낼 수 있다.
- $.ajax()는 jQuery 라이브러리를 별도로 설치해야 하지만 Fetch API는 별도 설치 없이 바로 사용 가능하다는 점과 Promise 기반으로 동작하는 장점이 있다.
- Promise를 사용하면 비동기 코드를 더 깔끔하고 읽기 쉽게 작성할 수 있고, then()과 catch()로 비동기 응답 처리를 간단하게 할 수 있어 코드 흐름이 명확해진다.
- .json() 메서드를 사용해서 응답 데이터를 JSON으로 변환한다.

```java
fetch('https://api.example.com/data')
.then(response => response.json()) // 응답을 JSON으로 변환
.then(data => console.log(data)) // 데이터 처리
.catch(error => console.error(error)); // 오류 처리
```

#### 1-3. Axios

- 비동기 요청을 도와주는 외부 라이브러리로, npm을 통해 별도로 설치(npm install axios)해서 사용한다.
- response.data 속성을 통해 응답 데이터를 바로 가져올 수 있다. (Fetch처럼 .json()을 따로 호출할 필요 없다.)

## 2. WebSocket (실시간 양방향 통신) 이란?

- REST API는 요청이 있을 때만 응답하지만, WebSocket은 서버와 클라이언트가 항상 연결된 상태로 데이터를 주고받을 수 있다.
- 예시로 실시간 채팅, 스포츠 경기 중계 등이 있다.

#### WebSocket의 핵심 특징

- 양방향(Full-Duplex) 통신
    - HTTP는 클라이언트가 요청을 보내야만 서버가 응답하는 단방향 구조지만, WebSocket은 연결이 한 번 맺어지면 서버도 클라이언트에게 먼저 데이터를 보낼 수 있다.
- 연결 유지(Persistent Connection)
    - HTTP처럼 요청마다 새로 연결하는 게 아니라, 한 번 연결(handshake)하면 그 연결을 계속 유지하면서 데이터를 주고받는다.
- 적은 오버헤드
    - 매번 새로 연결하지 않으므로 HTTP 요청보다 통신 비용(헤더 등)이 적다.

## 3. Server-Sent Events (SSE) 이란?

- 서버가 클라이언트에 일방적으로 데이터를 푸시하는 방식이다.
- 예시로 뉴스 속보, 실시간 주식 정보, 타임 세일 알림 등이 있다.

#### **SSE의 핵심 특징**

- 단방향(One-way) 통신
    - WebSocket과 달리 서버 → 클라이언트 방향으로만 데이터를 보낼 수 있다. 클라이언트가 서버로 데이터를 보내야 한다면 별도의 요청(fetch 등)이 필요하다.
- HTTP 기반
    - WebSocket처럼 별도 프로토콜(ws://)을 쓰지 않고, 기존 HTTP 연결을 계속 열어둔 채로 데이터를 스트리밍한다. 그래서 구현이 WebSocket보다 간단하다.
- 자동 재연결
    - 연결이 끊기면 브라우저의 EventSource 객체가 자동으로 재연결을 시도한다는 장점이 있다. (WebSocket은 재연결 로직을 직접 구현해야 한다.)

## RESTful 이란?

- REST(Representational State Transfer)는 웹에서 데이터를 주고받는 아키텍처 스타일 뜻하고, REST 원칙을 잘 지킨 API를 RESTful이라고 한다.
- REST의 설계 원칙(자원 기반 URI, 무상태성, 일관된 인터페이스 등)을 잘 준수하여 설계된 API를 가리키는 형용사적 표현이다.
- 즉, REST는 "원칙(스타일) 자체"를 의미하고, RESTful은 "그 원칙을 얼마나 잘 지켰는지"를 나타내는 말이다.
- 모든 REST API가 100% RESTful한 것은 아니며, 원칙을 일부만 따르는 API도 실무에서는 흔히 "REST API"라고 불리는 경우가 많다.
