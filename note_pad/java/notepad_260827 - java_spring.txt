web 이란?
인터넷을 통해 웹 브라우저에서 웹 페이지나 웹 애플리케이션 등의 정보를 주고받을 수 있도록 만든 시스템이다.

하이퍼 텍스트 : 인터텟 문서에 있는 문서와 문서를 클릭만으로 쉽게 이동하는 것이다.

스태틱 페이지(정적 페이지) : 클라이언트의 요청 발생시 항상 변화없는 웹페이지이다.
(HTML)

다이나믹 페이지(동적 페이지) : 검색, 로그인, 신용카드 결제와 같은 클라이언트의 요청에 따라 항상 변화하는 웹페이지이다.
(ASP, PHP, JSP 등)

JSP(Java Server Page) : 서버에서 실행되는 웹 페이지 기술로, HTML 코드 안에 Java 코드를 작성하여 동적인 웹 페이지를 생성할 수 있다.
JSP 파일은 클라이언트의 요청이 들어오면 서버에서 서블릿(Servlet)으로 변환·컴파일되어 실행된다.
서블릿으로 변환된 JSP는 사용자의 요청을 처리하고, 필요한 데이터를 DB 등에서 가져와 HTML 문서를 동적으로 생성한 후 클라이언트(웹 브라우저)에 응답한다.

Java Beans 이란?
	-JSP의 표준 액션 태그를 통해 접근할 수 있는 일반적인 Java 객체이다.
	-JSP 파일 내에서 사용할 수 있는 데이터 저장 및 전달용 객체라고 생각하면 이해하기 쉽다.
	-JSP에서 데이터를 주고받을 때 자주 사용되며, 뷰(JSP)와 데이터 및 로직을 분리하는 데 도움을 준다.
	-재사용하기 쉽도록 일정한 규칙에 따라 작성하며, 일반적으로 기본 생성자와 private 멤버 변수, getter/setter 메서드를 사용한다.

비즈니스 로직 : 클라이언트의 특정 요청에 대해 웹 애플리케이션이 처리해야 하는 실제 업무와 처리 과정을 의미한다.
(예를 들어 사용자가 id와 pw를 입력하여 로그인을 시도하면, 웹 애플리케이션은 입력받은 회원 정보가 DB에 저장된 정보와 일치하는지 확인하고, 로그인 성공 또는 실패 결과를 처리하는 과정이 비즈니스 로직에 해당한다.)

프레젠테이션 로직 : 클라이언트의 특정 요청에 대해서 웹 애플리케이션이 사용자에게 결과를 보여주거나 사용자의 입력을 전달하기 위해 처리해야 하는 화면 관련 과정이다.
(사용자가 id, pw를 입력해서 로그인을 시도할 때, 웹 애플리케이션에서는 로그인 화면의 입력값을 서버에 전달하고, 로그인 처리 결과에 따라 성공 또는 실패 메시지를 화면에 표시하는 과정이 프레젠테이션 로직에 해당한다.)

디자인 패턴 : 소프트웨어 개발에서 자주 발생하는 문제를 해결하기 위해 만들어진 재사용 가능한 설계 방법이다. 대표적으로 23가지의 디자인 패턴이 있으며, 각각 특정한 상황에서 객체와 클래스의 관계 및 구조를 효율적으로 구성할 수 있도록 한다.
(ex : 어댑터 패턴은 서로 호환되지 않는 인터페이스를 가진 객체들이 함께 동작할 수 있도록 연결해주는 디자인 패턴이다.)

JDK(Java Development Kit)
	-Java 프로그램을 개발하고 실행하기 위해 필요한 도구들을 모아놓은 개발 키트이다. 
	-Java 소스 코드를 컴파일하는 javac, 프로그램을 실행하는 java 등의 개발 도구가 포함되어 있다.

웹 서버 : 클라이언트의 요청이 스태틱 페이지인 경우, 웹서버에서 클라이언트에게 응답한다.
(Apache Server, IIS, Nginx 등)

웹 어플리케이션 서버 : 클라이언트의 요청이 다이나믹 페이지인 경우, DB에 질의하고, 응답받아서 웹서버에 반환하고 클라이언트에게 응답한다.
(Tomcat, JBoss, Jeus)

톰캣
	-웹 애플리케이션을 실행하기 위한 컨테이너이다.
	-Servlet, JSP 같은 Java 웹 프로그램을 실행할 수 있는 환경이 들어 있다.
	-컨테이너는 쉽게 말해 웹 프로그램이 실행될 수 있도록 필요한 것들을 관리하는 공간이다.
		-Servlet 생성 -> Servlet 실행 -> Servlet 종료 -> URL 요청을 Servlet에 연결 -> JSP 실행 -> Session 관리

Spring MVC 란?
	-Spring MVC는 사용자의 요청을 받아서, 역할에 따라 나누어 처리한 뒤 화면으로 응답하는 Spring 기반 웹 개발 구조이다.

[ Client (1. 요청)-> "DispatcherServlet" (2. 요청)-> HandlerMapping

HandlerMapping (3. Controller)-> "DispatcherServlet" (4. 요청)-> HandlerAdapter

HandlerAdapter (5. 요청)-> Controller

Controller (6. model & view name)-> HandlerAdapter (7. model & view name)-> "DispatcherServlet"

"DispatcherServlet" (8. view name)-> ViewResolver (9. view)-> "DispatcherServlet"

"DispatcherServlet" (10. model)-> View (11. 응답)-> Client ]

1. https://catsbi.oopy.io/f52511f3-1455-4a01-b8b7-f10875895d5b
2. https://programmer-may.tistory.com/161


각각의 역할에 대한 "개념 정리할 것"(DispatcherServlet가 중심적인 역할으로 매우 중요)


Client 란?
	-웹 애플리케이션에 요청을 보내는 사용자 또는 브라우저이다.
	-사용자가 브라우저에서 "http://localhost:8080/member/list" 주소를 입력하면, Client가 서버에 다음과 같은 요청을 보낸다.

DispatcherServlet 이란?
	-Spring MVC의 중심에서 모든 요청과 응답의 흐름을 관리하는 중앙 관리자다.
	-Spring MVC에서는 사용자의 요청이 바로 Controller로 가지 않고, 먼저 DispatcherServlet이 요청을 받는다.
	-DispatcherServlet은 요청을 받고 나서 HandlerMapping에게 물어본다.
	-DispatcherServlet의 주요 역할
		-Client의 요청을 가장 먼저 받는다.
		-HandlerMapping에게 Controller를 찾도록 요청한다.
		-HandlerAdapter를 통해 Controller 실행한다.
		-Controller가 반환한 Model과 View 이름을 받는다.
		-ViewResolver에게 View를 찾도록 요청한다.
		-Model 데이터를 View에 전달한다.
		-최종 결과를 Client에게 응답한다.

HandlerMapping 이란?
	-사용자의 요청을 처리할 Controller를 찾는 역할이다.
	-Client가 "/member/list" 요청을 보내면, HandlerMapping은 요청 주소를 보고 나서 요청된 주소와 연결된 Controller를 찾고, DispatcherServlet에게 알려줍니다.

HandlerAdapter 란?
	-찾아낸 Controller를 실제로 실행할 수 있도록 연결해 주는 역할이다.
	-DispatcherServlet은 HandlerMapping을 통해 Controller를 찾았다.
	-하지만 DispatcherServlet이 Controller를 직접 실행하는 것이 아니라 HandlerAdapter를 통해 실행한다.

Controller 란?
	-사용자의 요청을 받아 실제 작업을 처리하도록 연결하는 역할이다.
	-회원 목록 요청이 들어왔다면, Controller는 필요한 작업을 Service에 요청하고, 처리 결과를 받아와 View에게 전달할 데이터를 저장하는 것이다.
	-Controller가 DispatcherServlet에게 전달하는 것은 "Model + View Name:이다.
	
Model 이란?
	-Controller에서 처리한 데이터를 View로 전달하기 위한 데이터 저장 공간이다.
	-DB에서 회원 목록을 가져왔다면, 데이터를 화면에 보여줘야 하기 때문에 Model에 넣는다.

View Name 이란?
	-Controller는 실제 JSP 파일 자체를 직접 반환하지 않는다.
	-return "home";
	-"home"은 View Name이고, 실제 파일 위치는 ViewResolver가 찾아준다.
	
ViewResolver 란?
	-Controller가 반환한 View Name을 실제 View 파일 위치로 변환하는 역할이다.

View 란?
	-사용자에게 최종적으로 보여지는 화면이다.
	DispatcherServlet으로부터 Model 데이터를 전달받고, 저장된 다음에 JSP에서 사용할 수 있으며, 최종적으로 HTML을 만들어 Client에게 전달한다.

Spring Framework(스프링 프레임워크) 란?
	-Java로 웹 애플리케이션을 쉽고 체계적으로 개발할 수 있도록 다양한 기능을 제공하는 프레임워크이다.
	-개발자가 프로그램의 모든 구조를 직접 만들지 않아도 되도록, 객체 관리·웹 요청 처리·데이터베이스 연결 등의 기능을 제공하는 개발 도구의 틀이다.
	
왜 Spring Framework를 사용할까?
	-Java만으로 웹 프로그램을 만들면 개발자가 직접 관리해야 할 일이 많다.
	-필요한 객체를 직접 생성하고 서로 연결해야 하므로, 프로그램의 규모가 커질수록 객체 간의 연결과 관리가 복잡해진다.
	-Spring Framework는 이러한 객체들을 Spring Container가 관리하도록 만들어준다.

Spring Framework의 핵심 개념
	IoC(Inversion of Control) 란?
		-객체의 생성과 관리에 대한 제어권을 개발자가 직접 가지지 않고 Spring에게 맡기는 것이다.
		-기존 Java에서는 개발자가 직접 객체를 생성하지만, Spring에서 개발자는 필요한 객체를 직접 만들지 않고 Spring에게 맡긴다.
	DI(Dependency Injection) 란?
		-객체가 필요한 다른 객체를 직접 생성하지 않고, 외부(Spring)로부터 주입받는 것이다.
		-기존 Java에서는 Controller가 직접 Service를 생성하지만, Spring에서는 생성자 주입 방식이 일반적이다.
		
Spring Container 란?
	-Spring 애플리케이션에서 객체를 생성하고 관리하는 공간이다.
	-Spring에서는 관리되는 객체를 Bean이라고 부른다.

Bean이란?
	-Spring Container가 생성하고 관리하는 객체이다.
	-@Component, @Controller, @Service, @Repository 등의 클래스들은 Spring이 찾아서 Bean으로 등록할 수 있다.
	
AOP(Aspect Oriented Programming) 란?
	-여러 기능에서 공통적으로 필요한 작업을 따로 분리하여 관리하는 방식이다.
	
Spring MVC 란?
	-웹 애플리케이션에서 사용자의 요청을 처리하는 구조이다.
	-해당 패턴(구조)에서는 DispatcherServlet이 전체 요청과 응답 흐름을 관리하는 중심 역할을 한다.
	

공식 홈페이지 : https://spring.io/

Microservices
	-Quickly deliver production‑grade features with independently evolvable microservices.
	(각각 독립적으로 발전·변경할 수 있는 마이크로서비스를 통해 실제 서비스 수준의 기능을 빠르게 제공할 수 있다.)
	-하나의 큰 애플리케이션을 여러 개의 작고 독립적인 서비스로 나누어 개발하는 방식이다.
	
Serverless
	-The ultimate flexibility. Scale up on demand and scale to zero when there’s no demand.
	(최대의 유연성을 제공합니다. 요청이 많아지면 필요에 따라 확장하고, 요청이 없으면 사용량을 0까지 줄일 수 있다.)
	-서버가 아예 없는 것이 아니라 서버를 직접 관리하지 않고, 필요한 순간에만 서버 자원을 사용하여 프로그램을 실행하는 방식이다.

Batch
	-Automated tasks. Offline processing of data at a time to suit you.
	(자동화된 작업을 수행합니다. 원하는 시간에 데이터를 오프라인으로 처리할 수 있다.)
	-데이터를 사용자의 요청이 들어올 때마다 즉시 처리하는 것이 아니라, 일정량의 데이터를 특정 시간에 한꺼번에 처리하는 방식이다.

spring legacy 란?
	-전통적인 방식의 Spring Framework 프로젝트를 의미한다.
	-Spring Boot 이전에 주로 사용하던 Spring 개발 방식이다.
	
	| 구분      | Spring Legacy   | Spring Boot |
| ------- | --------------- | ----------- |
| 설정 방식   | XML 설정이 많음      | 자동 설정 중심    |
| 서버 실행   | Tomcat 등을 직접 설정 | 내장 서버 사용 가능 |
| 프로젝트 설정 | 직접 하나씩 설정       | 기본 설정 자동화   |
| 설정 난이도  | 비교적 복잡          | 비교적 간단      |
| 대표 프로젝트 | Spring MVC      | Spring Boot |

Maven 이란?

ava 프로젝트의 빌드(Build)와 의존성(Dependency) 관리를 자동화해 주는 도구입니다.

쉽게 말하면, 개발자가 프로젝트에 필요한 라이브러리 설치, 컴파일, 테스트, 패키징 등의 작업을 Maven이 설정에 따라 처리해 줍니다.

Maven이 없다면

필요한 라이브러리를 직접 다운로드하고 프로젝트에 추가해야 합니다.
Maven을 사용하면

pom.xml에 필요한 라이브러리를 작성하면 Maven이 자동으로 관리합니다.


Maven의 주요 역할
의존성 관리
프로젝트에 필요한 라이브러리를 자동으로 다운로드하고 관리합니다.
빌드 자동화
컴파일, 테스트, 패키징 등의 과정을 자동으로 처리합니다.
프로젝트 관리
프로젝트의 이름, 버전, 라이브러리 등의 정보를 관리합니다.

pom.xml이란?

Maven 프로젝트의 설정 파일입니다.

프로젝트 정보와 필요한 라이브러리, 빌드 설정 등을 작성합니다.


Maven Repository 홈페이지 : https://mvnrepository.com/

DB의 환경 구분
	Local DB
		-개발자의 개인 PC에서 실행하는 데이터베이스로 개발자가 기능을 만들고 테스트할 때 사용한다.
	Dev DB(like.깃허브)
		-개발팀이 함께 개발하고 테스트하기 위해 사용하는 공용 개발 데이터베이스로 Local에서 개발한 코드를 GitHub 등에 올리고 공유한 뒤, 개발 서버에서 함께 테스트할 수 있다.
	Real DB(상용) / Production DB(운용)
		-실제 사용자에게 서비스를 제공하는 운영 환경의 데이터베이스로 개발자가 Local DB처럼 자유롭게 데이터를 삭제하거나 수정해서는 안된다.
