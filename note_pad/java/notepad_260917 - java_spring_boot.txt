## 비동기 방식 이란?

- 웹 개발에서 비동기(Asynchronous) 방식은 요청을 보낸 후 응답을 기다리지 않고 다른 작업을 계속 수행할 수 있도록 하는 방식이다.
- 웹 브라우저(프론트엔드) 환경에서 비동기 코드는 주로 JavaScript로 작성한다.
- 비동기의 반대는 동기(Synchronous) 방식이다.
- 동기 방식이란?
    - 요청을 보낸 후, 응답이 올 때까지 다음 코드를 실행하지 않고 대기(block)하는 방식이다.
    - 작업이 순서대로(순차적으로) 처리되기 때문에 코드 흐름을 이해하기 쉽지만, 응답이 오래 걸리는 작업이 있으면 그 뒤의 작업들도 전부 지연된다.

| 비동기(Asynchronous) | 동기(Synchronous) |
| --- | --- |
| 클라이언트는 서버로 요청을 보낸 후 응답을 기다리지 않고 다음 작업을 진행한다. | 클라이언트는 서버로 요청을 보낸 후 응답이 올 때까지 기다린 후 다음 작업을 진행한다. |

#### 비동기 방식의 장점

- UI 블로킹 방지 (클라이언트 성능 향상)
    - 클라이언트는 요청을 보내고 서버의 응답을 기다리지 않고 다른 작업(화면 렌더링, 사용자 입력 처리 등)을 계속할 수 있다.
- 빠른 사용자 경험
    - 응답을 기다리는 동안에도 화면이 멈추지 않고 다른 UI 요소(버튼 클릭, 스크롤 등)가 정상적으로 동작하기 때문에, 사용자는 웹페이지가 느리다고 느끼지 않는다.
- 병렬 처리 가능
    - 여러 개의 요청을 동시에 보내고 각각의 응답을 별도로 처리할 수 있다.
    - 예를 들어 이미지 3개를 동시에 요청하면, 하나씩 순서대로 기다리는 것보다 훨씬 빠르게 전체 작업을 끝낼 수 있다.

## REST API 이란?

- REST(REpresentational State Transfer)는 웹에서 시스템 간에 데이터를 주고받기 위한 아키텍처 스타일(설계 원칙)이다.
- 이 원칙을 따르는 API를 REST API라고 한다.

## 1. REST API 종류

#### 1-1. AJAX (Asynchronous JavaScript and XML)

- 특정한 라이브러리나 모듈이 아니라, 비동기적으로 데이터를 주고받는 기술을 의미한다.
- 예전에는 XMLHttpRequest 객체를 사용해 AJAX 요청을 보냈지만, 요즘은 Fetch나 Axios로 대체되었다.
- XMLHttpRequest 이란?
    - 브라우저에서 서버와 비동기(또는 동기)로 데이터를 주고받을 수 있게 해주는 내장 객체(Built-in Object)다.
    - AJAX 통신의 원조 격 기술로, 자바스크립트 초기부터 지원되었다.
    - 사용법이 다소 복잡하고 콜백 기반이라 코드가 길어지는 단점이 있다.
- $.ajax() 이란?
    - jQuery 라이브러리에서 제공하는 AJAX 요청 함수다.
    - XMLHttpRequest를 내부적으로 감싸서(wrapping), 더 간단한 문법으로 비동기 요청을 보낼 수 있게 해준다.
    - 과거 jQuery가 널리 쓰이던 시절 AJAX 통신의 표준처럼 사용되었지만, 요즘은 Fetch API나 Axios로 대체되는 추세다.

#### 1-2. Fetch API

- JavaScript 기본 내장 기능으로 fetch() 함수를 사용해서 요청을 보낼 수 있다.
- $.ajax()는 jQuery 라이브러리를 별도로 설치해야 하지만 Fetch API는 별도 설치 없이 바로 사용 가능하다는 점과 Promise 기반으로 동작하는 장점이 있다.
- Promise를 사용하면 비동기 코드를 더 깔끔하고 읽기 쉽게 작성할 수 있고, then()과 catch()로 비동기 응답 처리를 간단하게 할 수 있어 코드 흐름이 명확해진다.
- .json() 메서드를 사용해서 응답 데이터를 JSON으로 변환한다.

```java
fetch('https://api.example.com/data')
.then(response => response.json()) // 응답을 JSON으로 변환
.then(data => console.log(data)) // 데이터 처리
.catch(error => console.error(error)); // 오류 처리
```

#### 1-3. Axios

- 비동기 요청을 도와주는 외부 라이브러리로, npm을 통해 별도로 설치(npm install axios)해서 사용한다.
- response.data 속성을 통해 응답 데이터를 바로 가져올 수 있다. (Fetch처럼 .json()을 따로 호출할 필요 없다.)

## 2. WebSocket (실시간 양방향 통신) 이란?

- REST API는 요청이 있을 때만 응답하지만, WebSocket은 서버와 클라이언트가 항상 연결된 상태로 데이터를 주고받을 수 있다.
- 예시로 실시간 채팅, 스포츠 경기 중계 등이 있다.

#### WebSocket의 핵심 특징

- 양방향(Full-Duplex) 통신
    - HTTP는 클라이언트가 요청을 보내야만 서버가 응답하는 단방향 구조지만, WebSocket은 연결이 한 번 맺어지면 서버도 클라이언트에게 먼저 데이터를 보낼 수 있다.
- 연결 유지(Persistent Connection)
    - HTTP처럼 요청마다 새로 연결하는 게 아니라, 한 번 연결(handshake)하면 그 연결을 계속 유지하면서 데이터를 주고받는다.
- 적은 오버헤드
    - 매번 새로 연결하지 않으므로 HTTP 요청보다 통신 비용(헤더 등)이 적다.

## 3. Server-Sent Events (SSE) 이란?

- 서버가 클라이언트에 일방적으로 데이터를 푸시하는 방식이다.
- 예시로 뉴스 속보, 실시간 주식 정보, 타임 세일 알림 등이 있다.

#### **SSE의 핵심 특징**

- 단방향(One-way) 통신
    - WebSocket과 달리 서버 → 클라이언트 방향으로만 데이터를 보낼 수 있다. 클라이언트가 서버로 데이터를 보내야 한다면 별도의 요청(fetch 등)이 필요하다.
- HTTP 기반
    - WebSocket처럼 별도 프로토콜(ws://)을 쓰지 않고, 기존 HTTP 연결을 계속 열어둔 채로 데이터를 스트리밍한다. 그래서 구현이 WebSocket보다 간단하다.
- 자동 재연결
    - 연결이 끊기면 브라우저의 EventSource 객체가 자동으로 재연결을 시도한다는 장점이 있다. (WebSocket은 재연결 로직을 직접 구현해야 한다.)

## RESTful 이란?

- REST(Representational State Transfer)는 웹에서 데이터를 주고받는 아키텍처 스타일 뜻하고, REST 원칙을 잘 지킨 API를 RESTful이라고 한다.
- REST의 설계 원칙(자원 기반 URI, 무상태성, 일관된 인터페이스 등)을 잘 준수하여 설계된 API를 가리키는 형용사적 표현이다.
- 즉, REST는 "원칙(스타일) 자체"를 의미하고, RESTful은 "그 원칙을 얼마나 잘 지켰는지"를 나타내는 말이다.
- 모든 REST API가 100% RESTful한 것은 아니며, 원칙을 일부만 따르는 API도 실무에서는 흔히 "REST API"라고 불리는 경우가 많다.

## 1. query string 방식이란?

- URL 끝에 ?key=value 형태로 파라미터를 붙여서 서버에 조건이나 데이터를 전달하는 방식이다.
- 주로 필터링, 검색, 정렬, 페이징 등 자원을 "조회하는 조건"을 표현할 때 사용한다.

```
GET /users?id=5
GET /users?page=2&size=10
GET /products?category=shoes&sort=price_desc
```

## 2. RESTful 방식이란?

- REST 원칙에 따라 자원(Resource)을 URL 경로 자체로 표현하고, 행위는 HTTP 메서드로 표현하는 설계 방식이다.

#### 2-1. 쿼리 파라미터 설계

- 자원을 검색·필터링·정렬 할 때 사용. 자원 자체를 특정 짓는 게 아니라 "조건"을 전달하는 용도이다.

```
GET /users?role=admin
→ role이 admin인 사용자들 조회

GET /posts?category=tech&page=1
→ tech 카테고리의 1페이지 게시글 조회

GET /products?minPrice=1000&maxPrice=5000
→ 가격 범위로 상품 필터링
```

#### 2-2. 경로 변수 설계(Path Variable)

- 특정 자원을 고유하게 식별할 때 사용. URL 경로 자체에 자원의 식별자(ID)를 포함한다.

```
GET /users/5
→ id가 5인 특정 사용자 조회

GET /posts/12/comments
→ 12번 게시글의 댓글 목록 조회

DELETE /products/30
→ id가 30인 상품 삭제
```

#### 2-3. 쿼리 파리미터 vs. 경로 변수

| 구분 | 쿼리 파라미터
(Query Parameter) | 경로 변수
(Path Variable) |
| --- | --- | --- |
| 용도 | 자원을 필터링·검색·정렬·페이징 | 특정 자원을 고유하게 식별 |
| 필수 여부 | 보통 선택적(optional) | 보통 필수(required) |
| 예시 | /users?role=admin | /users/5 |
| 의미 | "이런 조건에 맞는 것들을 줘” | "이 특정 자원을 줘” |
| 자원 여러 개 반환 가능 여부 | 가능 (목록 반환) | 보통 단일 자원 반환 |

## 3. RESTful과 query string 비교

| 구분 | RESTful (경로 변수)
/users/5 | Query String
/users?id=5 |
| --- | --- | --- |
| REST 원칙 부합 여부 | ✅ 권장되는 방식 | ⚠️ 비권장 (안티패턴에 가까움) |
| 의미 | "5번이라는 자원 자체"를 가리킴 | "id가 5인 것을 찾아줘"라는 조건 |
| URI의 역할 | URI 자체가 자원을 고유하게 식별 | URI는 자원 집합, id는 검색 조건일 뿐 |
| 계층 표현 | /users/5/posts/3 처럼 계층 관계 표현 용이 | /posts?userId=5&postId=3 식으로 평면적 |
| 가독성 | URL만 봐도 "5번 사용자"임을 직관적으로 파악 | id가 여러 개면 URL이 길고 복잡해짐 |

#### 비동기 코드의 전체 흐름

```
[list.html] 페이지 로드
→ [admins.js] DOMContentLoaded 이벤트 발생
→ [admins.js] fetchGetAdmins() 실행 → 비동기 요청 (GET /admin/admins)
→ [AdminController] /admin/admins 요청 수신
→ [AdminService] DB에서 관리자 목록 조회 (memberRepository.findAll())
→ [AdminController] JSON(Map) 형태로 응답 반환
→ [admins.js] 응답 받아서 .json()으로 파싱 → 화면(table)에 동적으로 렌더링
```

#### 비동기 코드의 계층별 역할 정리

| 계층 | 파일 | 역할 |
| --- | --- | --- |
| View (초기 화면) | list.html | 빈 테이블(<tbody>)만 먼저 렌더링, 데이터는 JS가 채운다, |
| Client (비동기 요청) | admins.js | fetch()로 서버에 비동기 요청하면, 응답을 JSON으로 변환하고, DOM에 삽입한다. |
| Controller | AdminController | /admin/admins 요청을 받아 Service 호출 후 JSON(@ResponseBody) 반환한다. |
| Service | AdminService | DB에서 관리자 목록 조회,하고 DTO로 변환한다. |

#### AdminController 코드

```java
package com.office.calendaradmin.admin;

import lombok.RequiredArgsConstructor;
import lombok.extern.slf4j.Slf4j;
import org.springframework.stereotype.Controller;
import org.springframework.web.bind.annotation.GetMapping;
import org.springframework.web.bind.annotation.RequestMapping;
import org.springframework.web.bind.annotation.ResponseBody;

import java.util.Map;

@Slf4j
@Controller
@RequestMapping("/admin")
@RequiredArgsConstructor
public class AdminController {

final private AdminService adminService;

// 관리자 목록 : /admin.css/list
@GetMapping("/list")
public String list() {
    log.info("list()");

    String nextPage = "admin/list";

    return nextPage;
}

// 관리자 목록 조회
@GetMapping("/admins")
@ResponseBody
public Object admins() {
    log.info("admins()");

    Map<String, Object> resultMap = adminService.admins();

    return resultMap;
}
}
```

#### AdminService 코드

```java
package com.office.calendaradmin.admin;

import com.office.calendaradmin.member.MemberDao;
import com.office.calendaradmin.member.MemberDto;
import com.office.calendaradmin.member.jpa.MemberEntity;
import com.office.calendaradmin.member.jpa.MemberRepository;
import lombok.RequiredArgsConstructor;
import lombok.extern.slf4j.Slf4j;
import org.hibernate.engine.spi.ManagedEntity;
import org.springframework.stereotype.Service;

import java.util.HashMap;
import java.util.List;
import java.util.Map;
import java.util.stream.Collectors;

@Slf4j
@Service
@RequiredArgsConstructor
public class AdminService {

final private MemberRepository memberRepository;

public Map<String, Object> admins() {
    log.info("admins()");

    Map<String, Object> resultMap = new HashMap<>();

    List<MemberEntity> memberEntities = memberRepository.findAll();

    List<MemberDto> admins = memberEntities.stream()
            .map(MemberEntity::toDto)
            .collect(Collectors.toUnmodifiableList());

    resultMap.put("admins", admins);

    return resultMap;

}
}
```

document.addEventListener("DOMContentLoaded", function (){

async function fetchGetAdmins() {
console.log('fetchGetAdmins()');

try {
    let response = await fetch('/admin/admins', {
        method: 'GET',
        headers: {
            'Content-Type': 'application/json; charset=utf-8'
        }
    });

    if (!response.ok) {

    let admins = data.admins

        let template = document.querySelector('#list-template').content.cloneNode(true);

        template.querySelector('.mod_date').textContent = admins[i].mod_date;
        document.querySelector('#section_wrap tbody').appendChild(template);
    }

} catch (error) {
    console.log('fetchGetAdmins() COMMUNICATION ERROR!!', error);

}
}
