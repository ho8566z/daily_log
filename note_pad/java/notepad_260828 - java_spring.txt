Spring 이란?

Java 기반의 애플리케이션을 쉽고 체계적으로 개발할 수 있도록 다양한 기능을 제공하는 프레임워크이다.


객체 관리 → IoC, DI
웹 요청 처리 → Spring MVC
데이터베이스 연동 → Spring JDBC, MyBatis 연동 등
트랜잭션 관리 → @Transactional
보안 → Spring Security

Spring Core란?
	-Spring Core는 Spring Framework의 핵심 기능을 제공하는 부분으로, IoC와 DI를 통해 객체를 생성하고 관리한다.

Spring Context란?
	-Spring이 관리하는 객체(Bean)를 저장하고 관리하며, 애플리케이션에서 필요한 객체를 사용할 수 있도록 해주는 기능을 제공한다.


Spring MVC(f/w) 이란?
	-Spring Framework에서 웹 애플리케이션을 개발하기 위한 웹 프레임워크이다.
	-웹 브라우저의 요청을 받아 적절한 Controller로 전달하고, 처리 결과를 View를 통해 사용자에게 응답할 수 있도록 하는 기능을 제공한다.

Spring Security(f/w) 이란?
	-Spring 기반 애플리케이션의 인증(Authentication)과 인가(Authorization), 보안 기능을 제공하는 프레임워크이다.
		-사용자가 누구인지 확인하고(인증), 해당 사용자가 어떤 기능이나 페이지에 접근할 수 있는지 확인(인가)하는 기능을 제공하는 보안 프레임워크이다.

Spring-tx 이란?
	-Spring Framework에서 트랜잭션(Transaction)을 관리할 수 있도록 기능을 제공하는 모듈이다.
		-여러 개의 데이터베이스 작업을 하나의 작업 단위로 묶어서 모두 성공하거나 모두 취소(롤백)되도록 관리하는 기능이다.

애너테이션 이란?
	-애너테이션은 클래스, 메서드, 변수 등에 특정 정보를 표시하여 프로그램이나 프레임워크가 해당 정보를 참고할 수 있도록 하는 기능이다.

| 애너테이션             | 역할                               |
| ----------------- | -------------------------------- |
| `@Controller`     | 해당 클래스를 Controller로 지정           |
| `@Service`        | 해당 클래스를 Service로 지정              |
| `@Repository`     | 해당 클래스를 DAO/Repository 역할로 지정    |
| `@Component`      | 해당 클래스를 Spring Bean으로 등록         |
| `@Autowired`      | 필요한 객체를 자동으로 주입                  |
| `@RequestMapping` | 특정 URL 요청을 Controller 또는 메서드에 연결 |
| `@RequestParam`   | 요청 파라미터를 메서드의 매개변수에 전달           |

Controller 코드
(Spring MVC에서 클라이언트의 요청을 받아 현재 서버 시간을 만들어 View(home.jsp)로 전달하는 과정)

사용자가 브라우저에서 "/"를 요청 -> Controller요청을 받아 해당하는 메서드를 실행 -> Model(n)을 통해 요청받은 데이터를 해당되는 .jsp의 파일이름을 반환 -> Spring이 [ 'prefix(= /WEB-INF/views/)' + .jsp(해당되는 jsp의 파일이름) + 'suffix(= .jsp)' ]으로 view를 만들어서 화면에 출력한다.

### Spring MVC 요청 처리 흐름

사용자가 브라우저에서 '/' 요청
↓
Controller가 요청을 받아 해당 메서드를 실행
↓
Controller가 Model에 필요한 데이터를 담음
↓
Controller가 View 이름(.jsp 파일명)을 반환
↓
Spring이 'prefix + View 이름 + suffix'를 조합하여 실제 JSP 파일의 경로를 결정
↓
'/WEB-INF/views/' + 'home' + '.jsp'
↓
'/WEB-INF/views/home.jsp'를 View로 사용하여 화면에 출력

Logger(System.out.println();을 대체하는 log찍는 방법) 란?
	-Logger는 프로그램의 실행 과정이나 상태, 오류 등의 정보를 로그(Log)로 기록하기 위한 기능이다.
	-System.out.println()처럼 콘솔에 정보를 출력하지만, 로그의 종류와 중요도를 구분하고 필요한 로그를 체계적으로 관리할 수 있는 기능이다.
	
DEBUG  → 개발 중 확인할 상세 정보
INFO   → 일반적인 실행 정보
WARN   → 주의가 필요한 상황
ERROR  → 오류 발생
	

Logger의 종류는?

| 종류          | 설명                                 |
| ----------- | ---------------------------------- |
| **JUL**     | Java에 기본 포함된 'java.util.logging'   |
| **Log4j**   | Apache에서 제공하는 로깅 프레임워크             |

| **Logback** | SLF4J와 함께 많이 사용하는 로깅 프레임워크         |
| **SLF4J**   | 실제 로그를 출력하기보다는 로깅 API를 제공하는 추상화 계층 |

<resources> 란?

사용자가 웹 페이지를 요청하면 DispatcherServlet이 요청을 처리하지만, CSS나 JavaScript, 이미지 파일까지 Controller가 직접 처리할 필요는 없다.

	<resources mapping="/resources/**" location="/resources/" />

{ AGE: <input type="number" name="m_Age"> -> @RequestParam Integer m_Age }

프레임워크의 자동 형변환 : number를 String으로 브라우저에서 전달받고, String에서 Integer로 받는다.


[ Spring MVC - @RequestParam과 자동 형변환 ]

<input type="number" name="m_Age">

→ 브라우저는 HTTP 요청 데이터를 기본적으로 문자열(String) 형태로 전달한다.

→ Spring Controller에서

@RequestParam Integer m_Age

를 사용하면 Spring의 데이터 바인딩 기능이 요청 파라미터의
문자열(String) 값을 Integer 타입으로 자동 변환하여 전달한다.

즉,

브라우저 입력값
    ↓
HTTP Request Parameter
    ↓
String "25"
    ↓ Spring의 데이터 바인딩 및 타입 변환
Integer 25
    ↓
@RequestParam Integer m_Age

Clent가 브라우저에서 입력한 데이터가 Dto와 getter & setter의 관계?


Client가 브라우저의 <input> 태그에 데이터를 입력하면, 해당 데이터는 HTTP 요청을 통해 서버로 전달된다.

Spring MVC는 전달받은 요청 데이터를 DTO(Data Transfer Object) 객체에 저장할 수 있으며, 이 과정을 **데이터 바인딩(Data Binding)**이라고 한다.

이때 일반적인 JavaBean 방식에서는 요청 파라미터의 이름과 DTO의 프로퍼티 이름을 기준으로 데이터를 연결하고, setter를 통해 DTO 내부에 값을 저장한다.

DTO에 저장된 데이터는 이후 getter를 통해 가져와 사용할 수 있다.


| 구성 요소               | 역할                                |
| ------------------- | --------------------------------- |
| **Client**          | 브라우저에서 데이터를 입력하고 서버로 요청을 전송       |
| **`input`의 `name`** | 서버에 전달되는 요청 파라미터의 이름              |
| **HTTP 요청 데이터**     | Client가 입력한 값이 서버로 전달되는 데이터       |
| **Spring MVC**      | 요청 데이터를 분석하고 DTO와 연결하는 데이터 바인딩 수행 |
| **DTO**             | Client로부터 전달받은 데이터를 객체 형태로 저장     |
| **Setter**          | 전달받은 데이터를 DTO의 필드에 저장             |
| **Getter**          | DTO에 저장된 데이터를 가져와 사용              |

MemberDto vs MemberVo vs Entity 차이점(VO : Value Object)


DTO(Data Transfer Object) 란?
	-계층 간 데이터를 전달하기 위한 객체이다.
	
VO(Value Object) 란?
	-값 자체를 표현하기 위한 객체이다.
	-VO에서는 객체를 구분할 때 고유한 식별자보다 객체가 가지고 있는 값이 중요하다.
	-주소를 표현하는 객체가 있는 경우
	public class Address {

		private String city;
		private String street;

	}

	-두 Address 객체의 모든 값이 같다면, 일반적으로 같은 주소라는 의미로 판단할 수 있다.

	Address A
	city = 대전
	street = 중앙로

	Address B
	city = 대전
	street = 중앙로

        ↓

	값이 동일하다면, 동일한 객체로 판단한다.

	-때문에 VO는 일반적으로 생성된 이후 내부 상태가 변경되지 않는 불변 객체(Immutable Object) 형태로 설계하는 경우가 많다.


Entity
	-고유한 식별자(ID)를 통해 구분되는 객체​이다.
	-Entity는 객체가 가지고 있는 값이 일부 변경되더라도 동일한 ID를 가지고 있다면 일반적으로 같은 객체로 판단한다.
	-회원 Entity의 경우
	
	public class Member {

		private Long id;
		private String name;
		private String email;

	}

	-회원의 이름이나 이메일이 변경되더라도 회원 ID가 동일하다면 같은 회원으로 판단할 수 있다.

	[Member]

	ID = 1
	Name = 홍길동

		   ↓ 이름 변경

	ID = 1
	Name = 김철수

		   ↓

	ID가 동일

		   ↓

	같은 Entity

	-특히 JPA에서는 Entity가 데이터베이스 테이블과 객체를 매핑하는 역할을 한다.



DTO vs VO vs Entity 차이점
구분		DTO		VO		Entity
의미		Data Transfer Object	Value Object	Entity
주요 	목적	계층 간 데이터 전달	값 자체를 표현	식별자를 기준으로 객체를 관리
핵심		데이터 전달		값		고유한 식별자(ID)
동일성 판단	용도에 따라 다름		값이 같은지 중요		ID가 같은지 중요
상태 변경		가능		일반적으로 불변으로 설계	가능
equals()	필요에 따라 구현	값 비교를 위해 중요	식별자 기준으로 설계하는 경우가 많음
예시		MemberDto	Address, Money		Member



DTO의 equals()와 VO의 관계
	-DTO도 필요하다면 equals()를 오버라이딩할 수 있다.
	-하지만 DTO의 핵심 목적은 데이터 전달이므로, 모든 DTO에서 값 기반 비교가 반드시 필요한 것은 아니다.
	-반면 VO는 값 자체가 객체의 의미를 결정하기 때문에 값 비교가 중요하다.
	-따라서 VO는 일반적으로 equals()와 hashCode()를 함께 오버라이딩하여 객체 내부의 값을 기준으로 동일성을 비교하도록 구현한다.
	-객체는 서로 다를 수 있지만 VO에서는 객체 내부의 값이 동일하다면 논리적으로 같은 값으로 판단할 수 있다.
