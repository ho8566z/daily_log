## Docker 란?

- 애플리케이션을 컨테이너(Container) 라는 격리된 환경에 담아서 실행할 수 있게 해주는 컨테이너 플랫폼이다.
- 정확히는 컨테이너를 만들고(build), 배포하고(ship), 실행하는(run) 전체 과정을 관리하는 도구라고 보면 된다.

#### 왜 필요한가?

- "내 컴퓨터에서는 되는데요?" 문제 해결 — OS, 라이브러리 버전 차이로 인한 환경 불일치를 없앤다.
- 개발 환경 · 테스트 환경 · 운영(배포) 환경을 동일하게 유지 가능하다.
- 서버 하나에 여러 애플리케이션을 가볍게, 독립적으로 띄울 수 있다.

#### 가상머신(VM)과의 차이

| 구분 | VM (가상머신) |  | Docker (컨테이너) |  |
| --- | --- | --- | --- | --- |
| 격리 단위 | 하드웨어 전체 가상화되어 있다.
(Guest OS 포함) |  | OS 커널은 공유하고, 프로세스만 격리한다. |  |
| 부팅 속도 | 수 분 |  | 수 초 |  |
| 용량 | 수 GB~ |  | 수십~수백 MB |  |
| 성능 | 오버헤드가 크다 |  | 호스트와 거의 유사하다. |  |

#### 포트 (Port)란?

- 하나의 컴퓨터(IP 주소)에서 여러 개의 프로그램/서비스를 구분하기 위한 번호이다.
- IP 주소가 "건물 주소"라면, 포트는 그 건물 안의 "호실 번호"
- 0~65535번까지 사용 가능 (2^16개)

### 대표적인 포트 번호

| 포트 | 서비스 |
| --- | --- |
| 80 | HTTP |
| 443 | HTTPS |
| 22 | SSH |
| 3306 | MySQL |
| 5432 | PostgreSQL |
| 8080 | 개발용 웹서버 (Tomcat 등) |

```
http://192.168.0.1:8080
       └─IP 주소─┘ └포트┘
```

- 같은 컴퓨터에서 웹서버(80)와 DB서버(3306)를 동시에 실행해도, 포트 번호로 구분되기 때문에 충돌 없이 동작할 수 있다.

#### 공인 IP(Public IP) 란?

- 인터넷에서 직접 통신 가능한, 전 세계에서 유일한(고유한) IP 주소이다.
- ISP(인터넷 서비스 제공업체, KT/SKT/LG U+ 등)가 할당한다.
- 전 세계에 딱 하나만 존재한다.(중복 불가)
- 외부에서 내 서버로 직접 접속하려면 공인 IP가 필요하다.

#### 사설 IP(Private IP) 란?

- 한 네트워크(집, 회사) 내부에서만 사용하는 IP 주소이다.
- 인터넷에는 직접 노출되지 않는다.(공유기가 NAT로 변환해준다.)
- 서로 다른 네트워크라면 중복 사용 가능하다.(우리 집 사설 IP와 옆집 사설 IP가 같을 수 있다.)

#### 로컬 IP(Local IP) 란?

- 일반적으로 사설 IP와 같은 의미로 쓰이지만, 문맥에 따라 좀 더 좁은 의미로 "내 컴퓨터 자체를 가리키는 주소"를 뜻하기도 한다.
- 192.168.0.5 같은 사설 IP를 흔히 "로컬 IP"라고 부른다.
- 127.0.0.1(localhost)는 자기 자신을 가리키는 특수 주소(loopback)로, 가장 좁은 의미의 "로컬"이다.

## 도커의 주요 데이터 관리 방식 비교

- 볼륨(Volumes)
    - 도커가 완전히 관리하는 영역(/var/lib/docker/volumes/ 등)에 데이터를 저장한다.
    - 가장 권장되는 방식이다.
- 바인드 마운트(Bind Mounts)
    - 사용자가 직접 지정한 호스트 시스템의 특정 경로(예: /home/user/data)를 컨테이너와 직접 연결한다.
    - 소스코드 실시간 반영(Hot-reload) 등에 주로 쓰인다.
- tmpfs 마운트
    - 디스크가 아닌 호스트의 메모리(RAM)에 데이터를 임시로 저장한다.
    - 컨테이너가 종료되면 데이터가 즉시 사라진다.

#### 볼륨(Volumes) 이란?

- 컨테이너의 데이터를 영구적으로 보존하고 관리하기 위해 사용하는 저장 공간이다.
- 도커 컨테이너는 기본적으로 일회성(Stateless) 성격을 가진다.
- 즉, 컨테이너 내부에서 생성되거나 수정된 파일은 컨테이너가 삭제되면 함께 사라진다.
- 볼륨은 이러한 데이터 유실 문제를 해결하기 위해 컨테이너 내부와 호스트(또는 도커가 관리하는 별도 영역)의 디렉토리를 연결해 주는 역할을 한다.

#### 컨테이너와 가상 머신 비교

| 종류 | 내용 | 비교 |
| --- | --- | --- |
| 가상머신(VM) | 운영체제를 통째로 흉내낸다. | 켜는 데 몇 분이나 걸리고, 램을 많이 소비하며, 컴퓨터 1대 기준으로 조금만 띄울 수 있다. |

#### Docker Images(도커 이미지) 란?

- 컨테이너를 실행하기 위해 필요한 모든 파일과 설정(프로그램, 소스코드, 라이브러리, 환경 변수 등)을 포함하고 있는 읽기 전용(Read-only) 템플릿(설계도)이다.
- 도커 이미지의 특징
    - 하나의 이미지를 기반으로 여러 개의 컨테이너를 생성할 수 있다.
    - 객체지향 프로그래밍의 '클래스'와 비유되곤 한다.
    - 기존 이미지 위에 새로운 설정을 얹어서 새로운 이미지로 만드는 레이어(Layer) 구조로 되어 있다.

#### Docker Container(도커 컨테이너) 란?

- 도커 이미지를 실행하여 격리된 환경에서 동작하는 인스턴스(실행 중인 상태)이다.
- 도커 컨테이너의 특징
    - 이미지로 컨테이너를 생성하면 독립된 파일 시스템, 네트워크, 프로세스 공간이 할당된다.
    - 객체지향 프로그래밍의 클래스로 만든 '인스턴스(객체)'에 비유할 수 있다.
    - 컨테이너 내부에서 파일을 수정하거나 삭제해도 원래의 이미지에는 영향을 주지 않으므로, 언제든 원본 이미지로 새로운 컨테이너를 다시 띄울 수 있다.

#### Docker Hub(도커 허브) 란?

- 도커 이미지들을 무료로 공유하고 저장할 수 있는 공식 퍼블리크 이미지 저장소(Registry)이다.
- 도커 허브의 특징
    - GitHub와 비슷한 개념으로 생각하면 이해하기 쉽다.(이미지의 소스코드 저장소가 아닌 빌드된 이미지 저장소)
    - 우분투(Ubuntu), MySQL, Nginx, Redis 등 전 세계 개발자들이 미리 만들어 둔 오픈소스 이미지를 검색하고 다운로드(docker pull)하여 바로 사용할 수 있다.
    - 내가 만든 커스텀 이미지를 이곳에 업로드하여 다른 환경에서도 쉽게 내려받아 쓸 수 있다.

#### 배포를 위해서는 Docker가 필요하다.

| Docker의 존재 유무 | 차이점 | 결과 |
| --- | --- | --- |
| Docker 없이 배포 | 서버에 Java, MySQL을 설치하고, 설정 파일을 직접 업로드한다. | 서버가 바뀌면, 처음부터 다시한다. |
| Docker로 배포 | 이미지를 서버로 업로드하고, “docker run” 명령을 입력한다.
(설정을 이미지 내부에 존재한다.) | 서버가 바뀌어도 “docker run” 명령만 입력한다. |
