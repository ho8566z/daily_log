## Docker 란?

- 애플리케이션을 컨테이너(Container) 라는 격리된 환경에 담아서 실행할 수 있게 해주는 컨테이너 플랫폼이다.
- 정확히는 컨테이너를 만들고(build), 배포하고(ship), 실행하는(run) 전체 과정을 관리하는 도구라고 보면 된다.

#### 왜 필요한가?

- "내 컴퓨터에서는 되는데요?" 문제 해결 — OS, 라이브러리 버전 차이로 인한 환경 불일치를 없앤다.
- 개발 환경 · 테스트 환경 · 운영(배포) 환경을 동일하게 유지 가능하다.
- 서버 하나에 여러 애플리케이션을 가볍게, 독립적으로 띄울 수 있다.

#### 가상머신(VM)과의 차이

| 구분 | VM (가상머신) |  | Docker (컨테이너) |  |
| --- | --- | --- | --- | --- |
| 격리 단위 | 하드웨어 전체 가상화되어 있다.
(Guest OS 포함) |  | OS 커널은 공유하고, 프로세스만 격리한다. |  |
| 부팅 속도 | 수 분 |  | 수 초 |  |
| 용량 | 수 GB~ |  | 수십~수백 MB |  |
| 성능 | 오버헤드가 크다 |  | 호스트와 거의 유사하다. |  |

#### 게이트웨이 & MSA 구조

| 게이트웨이 | 서버 시스템의 "현관문" 역할. 모든 요청이 처음 거치는 지점이다. |
| --- | --- |
| MSA(Micro Service Architecture) | 게이트웨이 뒤로 DB, 회원관리 등 기능별로 서버를 분리해서 구성하는 방식이다. |
- Docker 하나 안에서 여러 서비스를 각각 컨테이너로 띄워 운영하는 것도 가능

#### Docker는 Container System이다.

| 서버 | 배 |
| --- | --- |
| 각 서비스를 담는 컨테이너 하나하나 | 컨테이너 시스템(도커) |

### 기존 OS 기반 시스템의 문제점

- 하나의 물리 PC 위에 OS가 있고, 그 위의 모든 프로그램이 해당 OS에 의존해서 동작한다.
- 한 프로그램(예: 카카오 앱)이 바이러스에 감염되면 OS를 공유하기 때문에 다른 프로그램까지 전염될 위험이 존재한다.

### 가상화(하이퍼바이저) 등장

- OS로부터 독립하기 위해 하이퍼바이저 방식이 등장했다.(호스트 OS 위에 여러 개의 게스트 OS를 얹는 방식, 예: VM)
- 문제점: OS를 여러 개 띄우다 보니 메모리·CPU 자원 경쟁 발생하고, 무거워졌다.

### 컨테이너의 등장

- 하이퍼바이저의 문제를 해결하기 위해 등장한 것이 컨테이너 런타임이다.
- 컨테이너는 호스트 OS와 필요한 데이터만 주고받으며, 독립적인 커널이 아닌 런타임 레벨에서 격리한다.
- 결과: 하이퍼바이저 방식보다 훨씬 가볍고, 배포/운영(마이그레이션)이 쉽다.
- 이것이 로컬 컨테이너 시스템이며, Docker를 사용하면 이를 클라우드에도 올릴 수 있다.

#### 포트 (Port)란?

- 하나의 컴퓨터(IP 주소)에서 여러 개의 프로그램/서비스를 구분하기 위한 번호이다.
- IP 주소가 "건물 주소"라면, 포트는 그 건물 안의 "호실 번호"
- 0~65535번까지 사용 가능 (2^16개)

### 대표적인 포트 번호

| 포트 | 서비스 |
| --- | --- |
| 80 | HTTP |
| 443 | HTTPS |
| 22 | SSH |
| 3306 | MySQL |
| 5432 | PostgreSQL |
| 8080 | 개발용 웹서버 (Tomcat 등) |

```
http://192.168.0.1:8080
       └─IP 주소─┘ └포트┘
```

- 같은 컴퓨터에서 웹서버(80)와 DB서버(3306)를 동시에 실행해도, 포트 번호로 구분되기 때문에 충돌 없이 동작할 수 있다.

#### 공인 IP(Public IP) 란?

- 인터넷에서 직접 통신 가능한, 전 세계에서 유일한(고유한) IP 주소이다.
- ISP(인터넷 서비스 제공업체, KT/SKT/LG U+ 등)가 할당한다.
- 전 세계에 딱 하나만 존재한다.(중복 불가)
- 외부에서 내 서버로 직접 접속하려면 공인 IP가 필요하다.

#### 사설 IP(Private IP) 란?

- 한 네트워크(집, 회사) 내부에서만 사용하는 IP 주소이다.
- 인터넷에는 직접 노출되지 않는다.(공유기가 NAT로 변환해준다.)
- 서로 다른 네트워크라면 중복 사용 가능하다.(우리 집 사설 IP와 옆집 사설 IP가 같을 수 있다.)

#### 로컬 IP(Local IP) 란?

- 일반적으로 사설 IP와 같은 의미로 쓰이지만, 문맥에 따라 좀 더 좁은 의미로 "내 컴퓨터 자체를 가리키는 주소"를 뜻하기도 한다.
- 192.168.0.5 같은 사설 IP를 흔히 "로컬 IP"라고 부른다.
- 127.0.0.1(localhost)는 자기 자신을 가리키는 특수 주소(loopback)로, 가장 좁은 의미의 "로컬"이다.

## 도커의 주요 데이터 관리 방식 비교

- 볼륨(Volumes)
    - 도커가 완전히 관리하는 영역(/var/lib/docker/volumes/ 등)에 데이터를 저장한다.
    - 가장 권장되는 방식이다.
- 바인드 마운트(Bind Mounts)
    - 사용자가 직접 지정한 호스트 시스템의 특정 경로(예: /home/user/data)를 컨테이너와 직접 연결한다.
    - 소스코드 실시간 반영(Hot-reload) 등에 주로 쓰인다.
- tmpfs 마운트
    - 디스크가 아닌 호스트의 메모리(RAM)에 데이터를 임시로 저장한다.
    - 컨테이너가 종료되면 데이터가 즉시 사라진다.

#### 볼륨(Volumes) 이란?

- 컨테이너의 데이터를 영구적으로 보존하고 관리하기 위해 사용하는 저장 공간이다.
- 도커 컨테이너는 기본적으로 일회성(Stateless) 성격을 가진다.
- 즉, 컨테이너 내부에서 생성되거나 수정된 파일은 컨테이너가 삭제되면 함께 사라진다.
- 볼륨은 이러한 데이터 유실 문제를 해결하기 위해 컨테이너 내부와 호스트(또는 도커가 관리하는 별도 영역)의 디렉토리를 연결해 주는 역할을 한다.

#### Docker Images(도커 이미지) 란?

- 컨테이너를 실행하기 위해 필요한 모든 파일과 설정(프로그램, 소스코드, 라이브러리, 환경 변수 등)을 포함하고 있는 읽기 전용(Read-only) 템플릿(설계도)이다.
- 도커 이미지의 특징
    - 하나의 이미지를 기반으로 여러 개의 컨테이너를 생성할 수 있다.
    - 객체지향 프로그래밍의 '클래스'와 비유되곤 한다.
    - 기존 이미지 위에 새로운 설정을 얹어서 새로운 이미지로 만드는 레이어(Layer) 구조로 되어 있다.

#### Docker Container(도커 컨테이너) 란?

- 도커 이미지를 실행하여 격리된 환경에서 동작하는 인스턴스(실행 중인 상태)이다.
- 도커 컨테이너의 특징
    - 이미지로 컨테이너를 생성하면 독립된 파일 시스템, 네트워크, 프로세스 공간이 할당된다.
    - 객체지향 프로그래밍의 클래스로 만든 '인스턴스(객체)'에 비유할 수 있다.
    - 컨테이너 내부에서 파일을 수정하거나 삭제해도 원래의 이미지에는 영향을 주지 않으므로, 언제든 원본 이미지로 새로운 컨테이너를 다시 띄울 수 있다.

#### Docker Hub(도커 허브) 란?

- 도커 이미지들을 무료로 공유하고 저장할 수 있는 공식 퍼블리크 이미지 저장소(Registry)이다.
- 도커 허브의 특징
    - GitHub와 비슷한 개념으로 생각하면 이해하기 쉽다.(이미지의 소스코드 저장소가 아닌 빌드된 이미지 저장소)
    - 우분투(Ubuntu), MySQL, Nginx, Redis 등 전 세계 개발자들이 미리 만들어 둔 오픈소스 이미지를 검색하고 다운로드(docker pull)하여 바로 사용할 수 있다.
    - 내가 만든 커스텀 이미지를 이곳에 업로드하여 다른 환경에서도 쉽게 내려받아 쓸 수 있다.

#### 실제로 Docker를 어떻게 설치하는지?

- Ubuntu 저장소의 docker.io 패키지나 편의 스크립트(convenience script)도 있지만, 일반적인 Ubuntu 머신을 사용하는 기술 사용자에게는 Docker 공식 APT 리포지토리에서 Docker Engine을 설치하는 것이 권장되는 방식이다.

#### Ubuntu에서 Docker 설치 순서 (공식 방식)

1. 사전 패키지 및 GPG 키 등록
    
    ```powershell
    sudo apt-get update
    sudo apt-get install ca-certificates curl
    sudo install -m 0755 -d /etc/apt/keyrings
    sudo curl -fsSL https://download.docker.com/linux/ubuntu/gpg -o /etc/apt/keyrings/docker.asc
    sudo chmod a+r /etc/apt/keyrings/docker.asc
    ```
    
2. Docker 공식 저장소를 apt 소스에 추가
    
    ```powershell
    echo \
    "deb [arch=(dpkg --print-architecture) signed-by=/etc/apt/keyrings/docker.asc] <https://download.docker.com/linux/ubuntu> \(. /etc/os-release && echo "$VERSION_CODENAME") stable" | \
    sudo tee /etc/apt/sources.list.d/docker.list > /dev/null
    sudo apt-get update
    ```
    
3. Docker 엔진 설치
    
    ```powershell
    sudo apt-get install docker-ce docker-ce-cli containerd.io docker-buildx-plugin docker-compose-plugin
    ```
    
4. 설치 확인
    
    ```powershell
    sudo docker run hello-world
    ```

#### docker run() 이란?

- 이미지를 기반으로 새 컨테이너를 생성하고 실행하는 명령이다.
- 실행 단계
    1.  로컬 이미지 확인
        - 먼저 로컬(내 컴퓨터)에 해당 이미지가 이미 있는지 확인한다.
    2.  없으면 레지스트리에서 Pull(다운로드)
        - 로컬에 없으면 기본 레지스트리인 Docker Hub(또는 지정된 레지스트리)에서 이미지를 찾아 다운로드한다.
        - 이 단계가 사실상 docker pull 이미지명과 동일한 동작이다.
    3.  컨테이너 생성(Create)
        - 다운로드된 이미지를 기반으로 새 컨테이너를 생성한다.
        - 이 단계에서 p, v, e, -name 같은 옵션들이 적용된다.(네트워크, 볼륨, 환경변수 설정 등)
    4.  컨테이너 시작(Start)
        - 생성된 컨테이너를 실제로 실행한다.

#### MySQL Install(Linux)

```powershell
docker run -d --name shop-mysql -p 3306:3306 \
-e MYSQL_ROOT_PASSWORD=shop1234 \
-e MYSQL_DATABASE=shop \
mysql:8.0
```

| --- | --- |
| -d | 백그라운드로(detach) |
| --name | 컨테이너 이름은 직접 정한다. |
| -p 3306:3306 | 내 컴퓨터 3306 → 컨테이너 3306 |
| -e | 환경변수(enviroment) |
| mysql:8.0 | 이미지 이름 : 태그 |

#### docker exec() 명령

- 이미 실행 중인 컨테이너 안에서 새로운 명령을 실행하는 명령이다.
- docker run은 새 컨테이너를 만들지만, exec는 기존 컨테이너에 "들어가서" 뭔가를 실행하는 것이다.

#### 환경변수 설정 방식

| 방식 | 결과 |  |
| --- | --- | --- |
| 설정을 코드에 직접 | 비밀번호가 코드에 남고, git에 올라간다.
서버마다 바꾸려면 코드를 고쳐야 하고, 이미지를 다시 만들어야 한다. |  |
| 환경변수로 설정 | 코드에는 없지만, 띄울 때 넣는다.
서버마다 다르게 줄 수 있으며, 같은 이미지를 그대로 사용한다. |  |

!image.png

#### 컨테이너 ON/OFF

| 명령 | 컨테이너는 | 데이터는 |
| --- | --- | --- |
| docker stop | 멈춘다. | 남아 있다. |
| docker start | 다시 돈다 | 그대로 있다. |
| docker restart | 꺼졌다가 켜진다. | 그대로 있다. |
| ‘docker rm’ | 사라진다. | 같이 사라진다. |
