## 취업을 위한 필요 능력

1. 성실성
    - 맡은 일을 꾸준히 수행하고, 정해진 일정과 약속을 지키는 태도이다.
2. 책임감
    - 자신이 맡은 작업의 결과에 책임을 지고, 문제가 생기면 원인을 확인하고 해결하려는 태도이다.
3. 협업과 소통 능력
    - 팀원과 요구사항, 진행 상황, 문제점을 공유하고 서로의 작업을 연결하는 능력이다.
4. 적응력과 유연성
    - 새로운 기술, 개발 환경, 요구사항의 변화에 맞춰 학습하고 대응하는 능력이다.
	
	
## 동기(Synchronous) 방식 이란?

- 요청을 보낸 후, 응답이 올 때까지 다음 코드를 실행하지 않고 대기(block)하는 방식이다.
- 작업이 순서대로(순차적으로) 처리되기 때문에 코드 흐름을 이해하기 쉽지만, 응답이 오래 걸리는 작업이 있으면 그 뒤의 작업들도 전부 지연된다.

---

## 비동기(Asynchronous) 방식 이란?

- 요청을 보낸 후 응답을 기다리지 않고, 그동안 다른 작업을 계속 수행하는 방식이다.
- 작업이 끝나면 콜백, 이벤트, Promise, async/await 등으로 결과를 받아 처리한다.

#### 블로킹(Blocking)과 논블로킹(Non-blocking)

- 동기/비동기와 자주 섞이지만, 보는 관점이 다른 개념이다.
    - 블로킹/논블로킹은 호출된 쪽이 제어권을 바로 돌려주는지를 본다.
    - 동기/비동기는 호출한 쪽이 결과를 직접 챙기는지, 나중에 통보받는지를 본다.

---

## 동기 VS. 비동기

| 구분 | 동기(Synchronous) | 비동기(Asynchronous) |
| --- | --- | --- |
| 기다림 | 응답이 올 때까지 기다린 후 다음 작업을 진행한다. | 응답을 기다리지 않고 다음 작업을 진행한다. |
| 결과 처리 | 호출한 쪽이 결과를 직접 받아 처리한다. | 완료되면 콜백/이벤트로 통보받아 처리한다. |

#### 동기/비동기 + 블로킹/논블로킹 조합

| 구분 | 동작 |
| --- | --- |
| 동기 + 블로킹 | 끝날 때까지 멈춰서 기다린 뒤 결과를 직접 처리한다. (가장 흔하고 단순) |
| 동기 + 논블로킹 | 제어권은 바로 돌려받지만, 끝났는지 계속 직접 확인(polling)한다. |
| 비동기 + 논블로킹 | 제어권을 바로 돌려받고, 끝나면 콜백/이벤트로 통보받는다. (Node.js 등) |
| 비동기 + 블로킹 | 비동기로 만들었지만 결국 기다리며 멈추는 경우로, 성능 저하의 원인이 된다. |
