## Postman(포스트맨) 이란?

- API를 개발하고 테스트할 때 사용하는 도구예요. 주로 웹/앱 개발자가 백엔드 API가 제대로 동작하는지 확인할 때 사용한다.

#### Postman(포스트맨)의 주요 기능

- API 요청 테스트: GET, POST, PUT, DELETE 같은 HTTP 요청을 직접 만들고 서버에 보내서 응답을 확인할 수 있다.
- 컬렉션(Collection): 관련된 API 요청들을 묶어서 저장하고 관리할 수 았다.
- 환경 변수(Environment): 개발/스테이징/운영 서버 등 환경별로 URL이나 토큰 값을 다르게 설정할 수 았다.
- 자동화 테스트: 요청 후 응답 값을 검증하는 스크립트 작성이 가능하다.
- 문서화: API 명세를 자동으로 문서 형태로 만들어 팀과 공유 가능하다.
- Mock Server: 실제 백엔드가 없어도 가짜 응답을 만들어 프론트엔드 개발 진행이 가능하다.

#### 왜 많이 쓰는지?

- 브라우저에서 API를 테스트하려면 코드를 짜야 하지만, 포스트맨은 GUI로 URL, 헤더, 바디 등을 입력해서 클릭 몇 번으로 요청을 보낼 수 있어서 편리하다.
- 개발 과정에서 프론트/백엔드 협업 시 "이 API가 이렇게 동작하는 게 맞나?"를 빠르게 확인하는 용도로 많이 사용된다.

| 활성화 프로필 | spring.profiles.active=dev | spring.profiles.active=prod |

## Swagger VS. Postman

| 구분 | Swagger (springdoc-openapi) |  | Postman |  |
| --- | --- | --- | --- | --- |
| 주 목적 | API 명세 문서화 및 자동 생성 |  | API 요청 테스트 및 디버깅 |  |
| 동작 방식 | 코드(어노테이션)를 분석해 자동으로 문서·UI 생성 |  | 개발자가 직접 요청을 만들어서 실행 |  |
| 적용 위치 | 서버 코드에 통합 (@Operation, @Parameter 등) |  | 서버와 별개로 독립 실행되는 클라이언트 앱 |  |
| 문서화 | 코드와 100% 동기화됨 (자동) |  | 수동으로 문서화하거나 컬렉션 export 필요 |  |
| 테스트 시나리오 | 단순 요청/응답 확인 정도 |  | 시나리오 테스트, 스크립트, 자동화, 환경별 변수 관리 등 강력 |  |
| 협업 | 백엔드가 만든 API를 프론트가 바로 확인 가능 |  | 팀 단위로 컬렉션 공유, CI/CD 연동 가능 |  |
| 환경 분리 | 프로필(dev/prod)로 활성화 여부 제어 |  | Environment 기능으로 여러 서버 전환 |  |
| 인증 테스트 | 제한적 (Bearer 토큰 정도만) |  | OAuth, API Key 등 다양한 인증 방식 시뮬레이션 |  |
| 팀 공유 대상 | 주로 API 소비자(프론트엔드, 외부 개발자)에게 공개 |  | 주로 개발팀 내부에서 테스트/디버깅용 |  |
| 자동화 | 거의 없음 (문서 생성이 주 역할) |  | 테스트 스크립트, 뉴먼(Newman)으로 CI 파이프라인 연동 가능 |  |

#### localhost vs 127.0.0.1

| 항목 | localhost | 127.0.0.1 |
| --- | --- | --- |
| 의미 | "내 컴퓨터 자신"을 가리키는 도메인 이름(호스트명) | "내 컴퓨터 자신"을 가리키는 실제 IP 주소 |
| 범주 | 루프백(loopback) 주소의 별칭 | 루프백(loopback) IP 주소 자체 |
| 동작 방식 | 운영체제의 hosts 파일에서 127.0.0.1로 변환(resolve)됨 | 네트워크 레이어에서 바로 "나 자신"으로 처리 |
| 차이 | 이름으로 부르는 것 | 숫자로 부르는 것 |

## Collection 이란?

- Postman에서 관련된 API 요청들을 하나의 폴더처럼 묶어서 관리하는 기능이다.

#### Collection의 핵심 개념

- 여러 개의 API 요청을 낱개로 흩어놓지 않고, 하나의 프로젝트나 기능 단위로 그룹핑해서 저장하는 것이다.

#### Collection이 왜 필요한지?

- 정리: 회원 관련 API, 게시글 관련 API 등을 폴더별로 나눠서 관리한다.
- 재사용: 매번 URL, 헤더, 인증 정보를 새로 입력하지 않고 저장된 요청을 클릭만 하면 실행할 수 있다.
- 공유: 컬렉션을 export(JSON 파일)해서 팀원에게 공유하거나 Postman 계정으로 팀 워크스페이스에 공유할 수 있다.
- 자동화: 컬렉션 전체를 순서대로 실행해서 테스트 시나리오를 자동으로 돌릴 수 있다. (Collection Runner)
- 문서화: 컬렉션 자체를 API 문서처럼 활용 가능하다.(Publish 기능)
